# compiler_guaranteed — 编译器隐式同步的适用边界

## 基本信息

| 属性 | 值 |
|------|---|
| 异常编号 | compiler_guaranteed |
| 异常类型 | 静态预防说明（编译器同步机制） |
| 错误码 | 无（说明性条目） |
| 类别 | static_preventive |
| 性质 | 信任型 |
| 覆盖条目 | C-3：L52/L53/L74；C-5：L59，同步/计数器相关机制 |
| 检测时机 | 编译期与生成代码复核 |
| 报错模式 | 不由本说明推导异常是否不可达 |

## 触发条件

用户代码包含跨 pipe 访问、TQue、SetFlag/WaitFlag 或 TC-Low 直接搬运时，可返回本说明。出现这些 API 不能自动证明编译器覆盖了所有依赖，也不能证明缺少显式屏障就一定发生硬件冲突。

## 编译器保证依据

- 历史资料引用 `kernel_operator_block_sync_intf.h:38,41`，但本知识库没有对应版本源码、编译选项及完整生成指令，不能据此作跨版本的绝对保证。
- TQue/显式事件的同步与 TC-Low `__ca__`/`__cb__` 裸指针访问须分别分析。TC-Low 平坦路径不能直接套用 TQue 的同步结论；参见 l0a_rdwr_conflict。
- 已确认生成的同步指令覆盖当前 buffer 依赖时，无需重复插入同一屏障；无法确认时保留待验证项。
- HSET/HWAIT 与核内事件计数器不能混用上限。历史的 28/31 等数值需核对目标架构和事件机制，不能成为通用阈值。

## 用户行动建议

- 先确认 API 层级、编译器版本、buffer 依赖及实际生成同步。
- 当前依赖未被覆盖时，按目标 API 支持的事件/屏障补齐，再验证结果。
- 只有当前环境的证据能支持时才输出“已由编译器保证”；其他情况说明需要检查，不输出“无需任何修复”的笼统结论。

## 关联异常

- l0a_rdwr_conflict / l0b_rdwr_conflict / fixp_l0c_rw_conflict：分别核对实际依赖、同步和目标错误证据。
- hset_counter_overflow / flag_counter_overflow：分别核对事件类型和计数器证据；OOB 兜底不能验证计数器异常。

## 检测执行指引

- **无规则匹配**：信任型说明，不参与规则计分，不生成 code_blocks。
- 用户代码出现相关 API 模式时返回适用边界；已确认的 runtime 违规证据优先于泛化说明。
- 本文不给所有编译器版本、API 层级或硬件型号作同步保证。
