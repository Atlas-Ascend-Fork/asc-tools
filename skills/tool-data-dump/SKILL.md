# 配置 Runtime Dump，采集并比对目标数据

本 Skill 指导 Agent 配置 `acl.json`，采集模型或单算子工程的目标输入输出，并在有对应 golden 时定位异常调用、张量和元素坐标。请求仅涉及 Kernel 内部插桩、源码定位或精度修复时，说明范围即可，不主动改成输入输出 Dump 方案；同时包含数据采集或比对目标时，只处理这部分。

执行采集需要可运行的工程、复现输入和明确目标。精度比对还需要同一输入下对应观察点的 golden，可来自 CPU、GPU 或已验证的 NPU 运行。

| 任务类型 | 处理方式与交付内容 |
| --- | --- |
| 仅咨询配置或方案 | 提供有效 JSON、选项说明、配置加载方式和预期产物；不执行工程，无需 golden |
| 仅采集或解析 | 核对目标数据及其对应请求和调用后交付；无需 golden |
| 采集并比对 | 完成采集、解析、golden 配对和比对，输出数据层定位报告 |
| 已有数据或比对结果 | 核对来源，从尚未完成的阶段继续，复用已有有效结果 |

字段说明见[acl.json 参数参考](references/acl-json.md)，工程接入与排查见[配置与采集](references/capture.md)，比对与报告见[数据处理](references/compare.md)，完整流程见[演示场景](references/examples.md)。

配置与工具参数以执行端配套 CANN 版本和 NPU 支持范围为准；引用官方资料时附上包含完整 URL 的可点击链接。

## 流程与产物

| 采集内容 | 处理方式 | 用途与结论 |
| --- | --- | --- |
| `stats` 原生 CSV | 直接读取统计列，与对应 golden 的同名统计比较；无需 msaccucmp 解析 | 筛选可疑张量和补采范围；不能提供异常坐标或代替逐元素验收 |
| `tensor` 原始 Dump | `msaccucmp convert` 转换为 NPY，配对 golden 后用 `file_compare` 和工程判据比对 | 官方指标、逐元素差异、异常坐标及报告 |

按任务需要执行以下阶段。阶段 2 采集并核验文件后，stats 进入阶段 3，tensor 进入阶段 4；仅采集或解析时，完成相应核验即可交付。

沿用工程的文件组织方式，运行摘要、对应关系和候选清单可记录在同一份文档中，无需为每个阶段另建文件格式。

## 阶段 1：确认输入与运行方式

检查工程入口与元数据，记录运行摘要：

- 复现条件：工程位置、运行命令、输入与请求、CANN 版本、NPU 型号、配置入口，以及能否单独重跑目标请求。
- 执行方式：加载并执行模型计算图，或通过单算子 API、单算子模型、`<<<>>>` 直调执行。按实际接口选择模型路线 2A 或单算子路线 2B，不能仅凭 `.om` 后缀判断。
- 采集目标：目标模型或调用、已知异常输出、执行依赖、调用数量和张量规模。
- 比对资料：golden 覆盖的最终输出或中间点、文件及 key、方向与索引、shape、dtype、布局，以及工程判据、有效区和特殊值规则。

能复现且目标明确时进入 2A 或 2B；部分映射需实际数据才能确认时，先小范围采集。缺少运行条件时记录具体缺项；判据缺失仍可采集和描述差异，但不作验收判定。

只有最终输出 golden 时，优先采集对应输出，不能据中间 Dump 判断首个异常层。此时先记录预期对应关系，采集后再确认实际文件与 golden 的配对。

## 阶段 2：按工程类型采集 Dump

| 条件（按顺序判断） | 采集选择 |
| --- | --- |
| 用户已指定范围、方向或内容 | 核对支持条件后按请求配置；采集不以提供 golden 为前提 |
| 目标明确且数据量可接受 | 直接采集 `tensor`；核验异常边界时用 `dump_mode=all` 覆盖输入输出 |
| 范围大且有可配对的中间或多次调用 golden | 先采 `stats` 筛选候选，通常用 `dump_mode=output`，再定向补采 tensor |

配置时分别确认采集内容、方向、层级和对象，字段限制见[参数参考](references/acl-json.md)，JSON 示例见[配置组合](references/capture.md#acljson-的字段怎样组合)：

- `dump_data` 选择 `stats` 或 `tensor`；`dump_mode` 选择输入、输出或两者。
- `dump_level` 选择 op/kernel 层级；kernel 级采集仍限于输入输出，不包含 Kernel 内部变量。
- 模型通过 `dump_list`、`model_name`、`layer` 选择对象；`opname_range` 及黑名单仅在模型 Dump 且 `dump_level=op` 时生效。

两条路线均使用工程实际配置入口，并按以下时序启用：

1. 在首次有效的 `aclInit` 或配套显式 Dump 生命周期中启用，两种方式不可叠加。
2. 配置须在目标模型或单算子内部模型首次加载前生效；已缓存模型未必受中途配置影响。
3. 等待异步任务同步完成后，再结束采集窗口。

### 2A：模型 Dump

1. 全量采集使用 `dump_list:[{}]`，指定模型或节点时设置真实的 `model_name`、`layer`，按需配置范围或黑名单；设置 `dump_op_switch=off`。
2. 确认 `model_name` 与加载对象一致：文件加载可用文件名去后缀或 ATC 模型 JSON 顶层 `name`；内存加载使用该 `name`。
3. 按[模型配置 A/B](references/capture.md#四份可改写的配置)准备 JSON 和独立可写目录。优先复用已有模型信息；仅在融合后节点映射不足时，用配套 ATC 从已有 `.om` 导出模型 JSON，不重新转换模型或生成 golden。

### 2B：单算子 Dump

1. API 或单算子模型执行时，按[单算子配置 C/D](references/capture.md#四份可改写的配置)设置 `dump_op_switch=on`、采集内容和方向，建议 `dump_list:[{}]`。
2. kernel 直调按[Host 接入](references/capture.md#kernel-直调的-host-接入)核对 `aclDumpOpTensors`、配套头文件与库及真实张量描述；配置启用后，还需在 Host 显式提交采集。
3. 原地计算、输入输出别名或缓冲复用时，覆盖前采输入、launch 后采输出，保证 stream 依赖正确并等待完成。
4. 重复调用在不改变复现条件的前提下，优先用新进程仅运行目标请求；不能隔离时保留 Host 调用记录及原有依赖。`layer` 不能筛选同一 API 的某次调用，文件排序、task 编号和 `data_index` 也不能直接用作请求标识。

执行后核对接口返回、进程最终状态、日志和本轮目标文件，记录请求、模型/调用、方向与文件的对应。空目录或非目标文件按[采集故障表](references/capture.md#采不到预期文件时)排查，不能仅凭退出码判定成功。

raw 指原始 tensor Dump，不假定固定扩展名；同一调用可能有多个文件，同一 raw 也可能包含多个张量。需要确认具体方向、索引或内容时，进入阶段 4 解析。

切换内容、请求或配置时使用新目录。同一目标补采须保持输入、模型、计算参数和层级一致，并核对异常是否仍复现；不同轮次行为不一致时分别报告，不能拼接为同一次异常的传播证据。

原生 stats 不可用时记录失败情况；任务允许时可改采 tensor，其事后统计须单独标注，不能计作原生 CSV。

## 阶段 3：统计筛查（仅采 stats 时）

核对 CSV 的方向、索引、shape、dtype 和 format，再与对应 golden 比较 Max、Min、Avg、实际可用的 L2norm，以及 NaN、正负 Inf 计数。没有对应参考时，仅记录统计现象。

计数项精确核对，连续值使用明确的筛查阈值；统计筛查与工程逐元素验收判据须区分。阈值缺失时仅记录差值，不作通过判定。

按本次目标核对统计项，缺失项记为不可用并保留已有差异；使用辅助脚本时，同时遵守其必需列要求。

配对已确认且符合[脚本支持范围](references/compare.md#统计筛查怎样读)时，整理 pairs 后调用 [dump_stats.py](scripts/dump_stats.py)，传入 `--pairs stats-pairs.json --atol <统计绝对阈值> --rtol <统计相对阈值> --out stats-result`；针对工程的适配仅补充配对信息。

输出实际/golden 统计及差值、候选和理由、缺列或未匹配项，以及下一轮的请求、节点和输入输出采集范围。

需确认差异时，返回 2A/2B 补采候选及必要输入的 tensor；已有 raw 则进入阶段 4。统计一致仍可能存在排列或局部误差，需验证精度时继续比较 tensor。无法补采时报告统计发现及定位缺项。

## 阶段 4：解析原始 Dump 并配对 golden

使用配套 `msaccucmp.py convert` 将 raw 转换为 NPY，保存日志并确认目标数组实际生成；命令见[官方工具](references/compare.md#官方工具怎样选)。返回 0 或存在文件，不代表所有目标张量均已转换成功。

逐份确认 raw 与 NPY 的来源关系；需要比对时补充 golden 文件及 key，核对以下信息：

- 张量身份：请求、模型/调用、输入输出方向和索引；依据来源与元数据配对，不按文件顺序或数值相似度推测。
- 数据表示：shape、原始 dtype、布局及有效元素范围；NPY 格式不保证逻辑布局已对齐，类型表示变化须记录说明。
- 对齐依据：仅做有元数据依据的转换，不通过任意 reshape、裁剪或降精度消除差异。

仅解析时交付 NPY、日志及来源关系，无需 golden；需要比对时，可信配对进入阶段 5。

未匹配项不作精度结论：缺少实际数据则补采，缺少参考或映射则记录缺项，继续分析其他可信配对。没有可比数据时进入报告阶段。

## 阶段 5：精度比对并确认异常边界

已配对 NPY 使用 `file_compare`；golden 为 NPZ 时先按明确 key 导出 NPY。仅在模型 Dump 与参考已成套且节点映射可靠时，按需使用[整网 compare](references/compare.md#成套模型数据的可选比对)。

NPY/NPZ 配对已确认且判据符合[辅助脚本支持范围](references/compare.md#辅助脚本的输入输出)时，优先调用 [summarize.py](scripts/summarize.py)，传入 `--pairs tensor-pairs.json --out comparison`，由其调用官方 `file_compare` 并补充坐标、完整超差掩码和报告。针对工程的适配仅补充配对；判据超出支持范围时，沿用工程 evaluator。

`file_compare` 不提供异常坐标，坐标和完整掩码由辅助脚本或工程 evaluator 补充，无需为获取坐标而使用整网模式。

保留官方指标，按工程完整判据核验逐元素容差、有效区、允许超差比例及特殊值规则。相似度、推荐阈值和退出码不能代替验收；判据缺失时只描述可计算差异，不设置默认阈值。

已有有效结果核对数据来源、对应关系和判据后复用；批量比较按工具时限分段，并确认各项执行状态与结果。

按实际依赖关系核对候选输出及全部必要输入，包括常量、权重、偏置：

- 输入已不同：继续核验上游，寻找有参考的异常边界。
- 输入均一致、输出超差，且相关可比上游已核验：可报告已核验路径上的最早可观察偏差。
- 缺少参考或必要输入：说明定位限制，不能判定输入正常。

传播结论仅覆盖已核验的输入输出衔接。下游相同位置持续超差，不足以排除后续新增误差，也不构成源码根因结论。

需核验上游或补齐输入时返回采集或解析阶段；已有足够数据层结论，或剩余缺项无法通过本次采集解决时，进入报告阶段。

## 阶段 6：输出数据层定位报告

沿用已有格式或[报告骨架](references/compare.md#报告骨架)，只包含本次实际完成的内容：

- 采集范围与产物：配置、命令、日志、数据位置、请求/调用与张量对应关系，以及 golden 覆盖范围。
- 统计与精度差异：实际/golden 统计及差值、官方结果、工程判定、超差数量及比例、最大绝对/相对误差、原始坐标与双方值；NaN/Inf 单列。
- 定位结论与限制：已核验的输入输出边界、异常位置及传播、未匹配张量、采集失败和剩余缺项；仅采集或解析时交付相应产物即可。

交付前核对：正文数字来自同一份已核验结果，并注明对应请求与观察点；raw、NPY、golden 和结果可互相对应。异常区域必须由完整超差掩码确认，Top-K 仅展示样本。

结论止于数据层定位，不进入代码根因分析或精度修复。
