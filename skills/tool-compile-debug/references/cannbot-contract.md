# CANNBOT编译排障能力协作

本包负责当前编译任务的证据关联、按需查询和验证收据；CANNBOT基础技能提供已有领域能力。运行只加载锁定子集中当前需要的技能；安装数量不是调用数量。宿主通过实际技能发现位置加载，失败时记录错误并在允许路径读取已安装材料，不自动全量下载。

## 一次协作应闭合什么

传入问题、原错误片段、相关源码引用、有效命令或尚未确定的候选、精确SDK、请求目标及已知冲突。未取得的字段明确unknown，不为准备交接而扫描全仓。返回后逐项核：

1. 来源能追到原文、文件或实际工具结果；推断与事实分开。
2. 版本、架构、调用域和工程前提适用；上游示例默认值不覆盖当前合同。
3. 回答了当前缺口，能改变修法或补齐必要验证。
4. 与本地SDK声明和实际命令不冲突；冲突则局部核验，不能取更容易编译的一方。

搜索空页、分页过滤、加载失败分别记录。一次必要后续查询仍无证据就保留缺口或更换方法，不在技能间反复交接同一问题。

当前声明已足以证明局部修法时无需额外加载技能。反之，定向核查后仍有会改变修法的API、架构、布局或Tiling歧义，就按下表选一个基础技能带着具体问题查询；不必等到两次失败构建。加载成功只证明材料可读，必须另说明它补了哪条证据；没有用到就如实记录未采用。

## 能力覆盖与职责

| 编译排障需求 | 我方能力与CANNBOT协作 |
|---|---|
| 错误日志、首错/连锁错误、发生位置 | 我方diagnose；复杂格式保留未知与原文，宿主继续阅读 |
| 工具链、依赖、环境冲突 | 我方inspect环境/构建事实＋CANNBOT `ascendc-env-check` 技能 |
| SDK声明、版本、头文件 | 当前源码/命令＋CANNBOT `ascendc-docs-search` 技能；检索结果另核适用性 |
| API参数、模板、数据类型 | 我方可见性/构建机制＋CANNBOT `ascendc-api-best-practices` 技能 |
| SoC/SKU、SIMT、Regbase | CANNBOT `npu-arch` 技能、CANNBOT `ascendc-simt-best-practices` 技能、CANNBOT `ascendc-regbase-best-practice` 技能；保持目标 |
| Blaze/tensor_api与链接边界 | CANNBOT `ascendc-blaze-best-practice` 技能的排障分支＋实际命令/源码证据 |
| Tiling共享数据与生成契约 | 我方生产—消费取证＋CANNBOT `ascendc-tiling-design` 技能；布局变化要补行为验证 |
| 编译补丁的功能保持 | 核最终diff及原契约，按风险复用原工程验证入口；保留原输入、参考和判定规则，未完成项单列 |
| 明确授权的迁移 | CANNBOT `ascendc-blaze-migration` 技能；编译失败本身不授予迁移授权 |

这些是能力承接路径，不是逐项真机验收证明。9.0/9.1/9.2×910/950分别记录支持要求、资料适用与实际结果；未测试组合保持待验。精确版本未知时仍可处理通用语法/构建问题，版本敏感修法先补证。

## 使用上游流程时的边界

上游按需资料、真实编译命令、原问题/恢复记录和验证分层应保留。既有工程修复不默认生成开发PLAN、不重建整套工程、不改上游资产。选其咨询或调试模式；确实需要新UT、探针或行为回归时，再执行对应范围。

主流程可在OpenCode或Claude Code单会话中完成。子代理可选，必须显式传递证据和任务；不能假设同名Task/Explore工具存在或拥有历史上下文。记录发现、加载、执行与证据采纳四个环节，避免“安装了但没使用”的结果被误解释为能力对比。
