# template_error — C++ 模板/重载/转换错误

## 根因

模板实例化、重载决议或转换失败。常见线索包括Tensor dtype不符、模板参数缺失、重载二义和候选条件不满足；分类是检索入口，不直接决定该改声明还是调用。

## 典型报错（真实日志样貌）

```
error: no matching function for call to '...'
error: call to '...' is ambiguous
error: no type named '...' / template argument deduction/substitution failed
error: invalid conversion from 'X' to 'Y'
```

上述字样也可能出现在API签名、目标门控或其他错误的级联日志中；保留完整首错和note链，不要仅靠正则片段推断唯一根因。

## 修法

先读编译器给出的候选声明、模板实例化链和拒绝原因，再对照实际实参及任务契约。相关 README、接口说明或用户要求若规定标量/向量实现、设备调用方式或特定计算路径，修复也须保留这些约束；结果看似相同或 SDK 支持另一重载，不代表允许替换实现。日志已指明声明位置时直接读取，不默认搜索整个库。多层级联先找到最早不满足的类型组合，再查实例参数、宿主分配/传参和实际读写类型；下游模板报错不自动说明公共模板缺特化。

先区分**模板参数推导**与**推导后的实参转换/引用绑定**。例如`template<class T> void f(Tensor<T>, const int32_t&)`的末参不含模板参数；可转换的整数实参可以生成临时值再绑定该const引用，不能仅凭有引用或整数类型不同就断言推导失败。相反，`template<class T> void g(T, const T&)`可能从两个位置推导出冲突类型；非const左值引用也不能靠同样的临时值绑定。判断依据是具体声明及编译器拒绝原因，不是“模板函数不做隐式转换”的概括。规则来源：[模板调用推导](https://eel.is/c++draft/temp.deduct.call)、[引用初始化](https://eel.is/c++draft/dcl.init.ref)。

只有重载列表、没有实际调用与完整note链时，说明还缺什么，不臆测实参类型或直接给窄化cast作为修法。随包签名是版本限定的候选证据，不是本机已核实的声明，也不是完整SDK清单；未找到其他重载不证明它不存在。确需转换时核值域、符号和单位，可编译不等于数值保持。

| 证据 | 修复取舍 |
|---|---|
| 推导冲突或二义 | 核目标实例及各参数的用途；实例已确定时才显式给模板参数，不能选一个能编译但语义不同的重载 |
| 整数/标量类型冲突 | 核值域、符号、单位和结果精度；声明与调用均可为修复点，不能为了匹配候选任意cast |
| Tensor dtype或指针类型不符 | 核真实存储dtype、元素数、布局和地址空间；强转指针不会转换缓冲中的数据或修正布局 |
| 参数个数或顺序不符 | 按准确版本声明确认每个参数的意义；不能删掉携带必要功能的参数，只为凑签名 |
| 返回值改为引用或传出参数 | 核它是写入新结果，还是读取调用者已有对象/句柄；参数能绑定不代表初始化及状态有效，见下节 |
| 候选被目标宏/约束排除 | 核实际SoC、头入口和模板条件；按用户目标解决，不切换无关目标制造通过 |
| 编译器建议的近似符号具有不同 Host/Device 归属 | 核调用位置、声明限定及实际用途；建议名称不是修法，设备专用 API 不能因拼写相似就替换进 Host 调用 |

若实例参数与既定数据契约冲突，恢复实例关系；不能为保留错误参数而给公共模板增加特化、改变累加类型或放宽断言。只有原功能确实要求新类型组合、实现也满足该组合约束时，才考虑扩展公共实现。以当前 SDK/项目声明和消费方为准，相邻示例仅辅助理解；证据足够后直接验证，不为确认相同结论继续追上游分支或提交历史。

### 数据类型要贯通分配、计算与写回

混合精度允许存储、标量、累加和输出类型不同，不能将它们全部改成同一种类型来消除模板错误。
沿实际调用核输入生成与Host分配字节、复制长度、Kernel的元素解释、显式转换、累加类型及最终写回。
若最终输出别名还指向错误的宽类型，只改公共epilogue使实例能编译，仍可能与Host缓冲大小和布局冲突。
另一个消费方编译通过也不能证明这一数据路径正确。

对照任务与这些证据，区分错误实例装配和公共实现确实缺少合法类型组合。前者恢复局部类型关系；
后者才修改公共实现并回归受影响消费者。实际存储布局与精度尚不明确时继续取证，不凭同名类型或
相邻示例判断。类型恢复后，已由数据流排除的风险不必重复验证；残留转换、尾块或写回风险按原用例补验。

### tile、stage和容量约束要一起满足

只在报错或补丁涉及这些参数时核对，不给普通名称修复追加全硬件盘点：

1. 把失败断言还原为当前实例的具体约束，代入实际参数，查相关循环、搬运或消费者为何需要它。
   大小关系、整除关系和每级tile的合法形状并不等价，满足其中一个不能推导其余条件成立。
2. 对候选改动核同一存储区的实际占用：按布局及对齐算每块字节，再结合同时存活的buffer/stage、
   固定预留和临时空间。分时复用不重复计数；L1、L0A、L0B、L0C与UB各自核容量，不能相互借用。
   容量与允许stage数以目标SDK/实现为准，不把一种架构的数值当通用常量。
3. 增大外层tile、缩小内层tile或改变stage都是有条件候选。选择同时满足任务实现、容量、对齐、
   循环和同步关系的修改，不删断言、不擅换dispatch路径；有多个合法候选时可接受不同修法，
   没有性能实测就不宣称其中一个更快。

随后按原目标构建；边界分支、资源复用或流水行为仍有风险时，用能到达该路径的既有合法输入检查，
不是只运行一个绕过新配置的小shape。编译断言通过与该次运行通过分别记录。

### 返回值与引用参数的契约差异

仅在更换这类 API 时，沿实际生产方到消费方核数据流，而不是只对照签名：

- 引用/指针形参不自动意味着纯输出。读当前版本声明及必要实现：谁分配存储、写入地址或句柄，谁只等待、查询或消费已有对象，调用前需要什么状态？默认构造也不自动获得有效资源。
- 若资源在一个函数的局部对象中分配，另一个函数重新声明同名对象，不会因此继承地址、队列项或所有权。核调用间如何传递同一有效对象/句柄，以及消费、释放、同步时其生命周期是否仍成立；有资源关联时不能用赋零、空对象或强转掩盖缺失。
- 若文档和实现明确允许由被调函数完整初始化输出，调用者无须先分配同一资源；已有对象跨调用传递且生命周期有效，也可采用引用重载。不要因一种重载需要已有句柄，就禁止所有传出参数修法。

替代重载与当前实例配置相容，不等于该配置本身正确。配置未被用户要求、且与实际生产/消费关系冲突时，修正有证据支持的实例配置可能比改写调用链更小；若该配置有明确用途或实现要求，则保留它并满足相应 API 的真实前提。编译通过无法替代这项判断。补丁涉及仍未排除的状态/生命周期风险时，补相关既有运行检查；无法运行则明确未验证范围，不把通过编译写成语义风险已解除。

若声明和调用位置已排除某个候选，不必专门把已知不适用的替换写入源码再编译证明。仍有会改变修法的疑问时，可用隔离副本和真实编译命令做定向探针；参数或 include 无法复现时，改用原目标构建，不把探针环境的缺失声明当成原错误。删除调用另需证明它不承担任务所需计算、状态或副作用，不能仅凭符号不存在就删。

形成一个有源码依据的局部修复后，用原工程验证。新错误按SKILL.md接续诊断；按具体补丁核接口、dtype、布局和功能保持，可使用当前源码、声明与依赖证据。仍不能排除相关数值风险时，才补针对性的合法输入与独立golden；不因类别或文件涉及计算、tiling、缓冲就固定要求NPU运行或数值测试。
