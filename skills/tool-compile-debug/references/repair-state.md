# 修复进展与构建恢复

简单任务只保留日志、最终diff和验证记录。复杂任务在本次输出目录维护简短记录：

- 当前问题及原文引用；用户要求的接口、算法、目标和配方。
- 有证据的事实及适用单元/配置；当前假设、支持与反证；下一步要区分的缺口。
- 已修改内容、未覆盖范围、仍有效的构建结果和在途`run_dir`。

记录可核对的依据和行动，不保存模型内部推理；不复制全会话，不把假设升级为工具事实。源码或配置变化后重核受影响的解释，其余事实继续使用。新生成文件使旧的“找不到”失效；同文件不同宏或target不能共享生效声明结论。

## 查询已有构建

```bash
python3 "/实际技能目录/scripts/run.py" verify --observe-run "/本次执行记录目录"
```

`request.json`在执行前保存命令、cwd、源码身份、完整传入环境的摘要与超时，不保存环境变量值；`running.json`包含进程身份；`build.log`由被测进程直接写盘；`result.json`是原子完成收据。观察同时核对请求与终态身份，环境变化不能复用旧配置收据。父宿主结束不等于该构建结束。记录应放持久工作盘；缓存目录丢失时不能补记成功。

| 观察 | 下一步 |
|---|---|
| running，身份仍匹配 | 等待/观察原运行，不另启动 |
| 结束收据有效，日志hash一致 | 收取执行结果；核被测源码/配置是否仍匹配，再检查覆盖与保持要求 |
| interrupted或unknown，无终态 | 保留部分日志，核本任务进程和启动窗口；不能自动重试或声称成功 |
| 身份不符或日志被改 | 原记录不可作当前验证依据，先查明冲突 |
| failed且捕获完整 | 解析本次失败，区分原问题、新阻塞、补丁回归与环境失败 |

`*.log.runs/active.json`防止同一逻辑输出位置并发派发。终态worker核所有权后释放标记；骤停留下的未知标记不自动删。若需处置，先核对应run、Linux boot ID/start ticks及其所属进程；只能处理本任务，不能按进程名全局kill。观察接口不负责杀进程或重派发。

独立执行收据不是有效修复结论：退出0还需原目标覆盖、有效产物和实现保持。模型超时后独立重编译成功应另记，不能改写原会话结局。

## 收取验证结论

新验证会保存恢复记录。长任务开始时显式指定一个尚不存在的、位于持久盘的目录，便于调用方中断后找到它；不指定时目录位于工作根的`verification/<唯一ID>`，正常报告的`recovery.directory`也会给出位置。

```bash
python3 "/实际技能目录/scripts/run.py" verify --case "/工程路径" \
  --soc Ascend910B1 --recovery-dir "/本次输出/verification-001" \
  --json-out "/本次输出/verify.json"
python3 "/实际技能目录/scripts/run.py" verify \
  --recover-verification "/本次输出/verification-001" \
  --json-out "/本次输出/recovered.json"
```

第一条的目标、配方及额外参数按原任务填写。第二条只收取原阶段并重算覆盖、错误比较和保持检查；不会构建、打补丁、重试或继续尚未启动的阶段。恢复输出须是记录目录外的新文件，防止覆盖旧证据。必须同时保留恢复目录、工作副本、原始输入与前态文件、执行收据、日志和编译证据；仅复制`session.json`不能恢复。

`recovery.status=collected`表示收取完成，具体是否编译通过仍看`transition`、`compilation_evidence`与`validation_scope`。`new_build_invoked=false`表示本次收取没有新构建，顶层`build_invoked`仍描述原运行。恢复查询不计作新的修复机会。

`verification_incomplete`与`recovery.gaps`保留以下缺口：调用进程仍活跃或身份未知、尚未派发、无终态见证、补丁或after阶段未完成、应由原流程决定的重试未完成、证据或输入变化、旧版本不含恢复记录。不会自动补跑。若已有历史报告，会放在`historical_result`，它不表示当前输入仍通过。

普通工程、CATLASS、CANN-ops和HCCL都通过同一阶段记录与适配器汇总；只有原流程所需的最后阶段已经执行、其证据完整时才可收取全局结论。文件内容、对象时间戳、原目标/参数、已配置应覆盖源码、工具实现和相关环境身份参与核验。SDK使用编译器路径/大小/时间戳及已发现依赖的内容绑定，不等于整个SDK的不可变镜像；环境不同或未知时不迁移结论。

终态证据采集最多50,000个文件、累计1GiB内容，单depfile解析上限4MiB；超限、不可读或依赖解析缺口使恢复未完成。目录枚举和整个SDK尚没有完整时间预算；大型框架要单独验证成本。功能和数值验证义务按原任务与本次补丁风险确定；恢复只收取已有证据，不替代尚未完成的必要验证。
