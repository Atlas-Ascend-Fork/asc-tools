# 技能触发评测

[trigger-evals.json](../evals/trigger-evals.json)用于检查宿主是否在合适的请求下加载本技能。
它包含带理由的正反场景，不是模型运行结果，也不是实际编译修复记录。
数据遵循 `skill_name`、`eval_mode: skill_trigger`、`cases` 的结构；每例包含
`id`、`context`、`prompt`、`should_trigger`、`reason` 和 `category`。

## 判定对象

- `should_trigger: true`：根据当前请求及上下文，应加载本技能。已有算子的编译失败已经明确时，
  即使尚缺完整日志、当前机器没有 CANN 或还要核对现场，也可以先加载指导。
- `should_trigger: false`：当前请求不需要加载本技能。宿主仍应完成用户的运行、精度、性能、
  开发、用法咨询或文本处理任务；这个标签不指定必须调用哪个其他技能。
- 加载不等于执行脚本、修改代码或真实编译。技能是否被加载与后续回答、操作是否正确分开评估。
- `context` 仅描述已发生的对话背景，不是系统指令；空字符串表示本例没有额外背景。
  `reason` 和 `category` 用于评审与分组统计，不能作为提示提供给被评估的选择流程。

本集覆盖配置、头文件、源码、API、架构选项、链接、打包和修复验证，以及不完整现场、
离线日志、上下文延续和英文请求。负例包含同领域的运行、精度、性能、完整开发和一般工具咨询，
也包含非 Ascend C 编译、偶然提到技能名、引用历史错误和已转向其他任务的上下文。
这些标签检查当前意图，不以错误词或工具名出现次数作为判定规则。

## 与回答评测的区别

两套材料有不同的实验前提，不能合成一个“触发率”：

| 集合 | 题面与前提 | 验收对象 |
|---|---|---|
| `trigger-evals.json` | 自然请求和必要领域背景；正例不点名本技能，不预载正文 | 宿主是否在该用和不该用时作出正确选择 |
| `evals.json` | 明确请求加载本技能、评审编译修复场景；允许读取指引，禁止工程操作 | 实际加载后的决策、证据判读和职责范围 |

回答集的加载断言是实验前提检查，不能当作自动发现能力。若请求禁止所有工具，就不能同时要求
调用技能；只作方案意味着不执行工程命令，不等于禁止读取技能。各题须自含领域和材料，不能依赖
上一题的“同样要求”或虚构前序加载事件。参考答案、断言和评分门槛不提供给被测会话。

[evals.json](../evals/evals.json)中的 `contains`、`not_contains` 检查回答文本；
`skill_activated` 是正向激活断言。没有写 `skill_activated` 不代表验证了“未激活”，
回答中说“这不属于编译问题”也不能证明技能此前没有被加载。

文本锚点只检查是否讨论了相应主题，不承担自然语言的否定判定。不得把错误动作或错误结论的
原句设为 `not_contains`：正确回答可能否定或引用它，例如“不由本技能接管精度排查”包含
“由本技能接管精度排查”。当前回答集使用正向主题/状态锚点；是否采纳错误建议、是否越界，
按 `expected_output` 做语义复核。范围外场景还须核实际加载事件。只通过文本锚点不能报告
行为通过；同义但未命中锚点的回答保留原始文本结果，并另记语义裁决。回执字段须保留实际名称和状态；固定交付结论仅在适用条件成立时使用，不能为命中词句改变修复决策。
修改断言时同时回归正确否定句和引用后明确拒绝的表达，不只检查参考回答自身。

区分固定协议名称与自然语言表述。字段、状态等名称需要精确对应；同一决策的不同正确说法不应
因缺少某个中文短语被拒绝。case-9保留实际加载与`tolerated`字段锚点；改名与删功能的区分、
真实接口/调用契约核查及按风险补验证，继续由完整`expected_output`评审，不要求出现“两种形态”、
“声明”或“重验”的原词。正例须包含这些要求的不同表述，反例须包含用词齐全但错误判为完成的回答，
以检查判定是否依赖含义。该修订前后的原始文本断言结果分别记录，不回写旧通过率。

回答题统一明确要求查阅本技能、评审其决策，须记录实际加载，并按`expected_output`核验。
其中17/18检查退出及重入条件。文本锚点“精度”和“运行”仅确认主题，不能替代职责边界的语义义务。
这里的加载来自明确的指引评审请求，不是对独立精度/运行任务的自动触发。

原17/18的自然请求原样保留为`trigger-evals.json`中的`negative_original_text_case_17/18`，要求完整会话不加载本技能、不执行编译修复工具。宿主可按用户意图处理范围外任务，不能把宿主自身的回答当作本技能接管。原版回答题的全部复现结果仍单列保留；修订题通过不改写原题结果。

区分未加载与已加载后的职责边界：未加载本技能时，宿主自行回答或选择其他技能，不直接归因为本技能路由；核description是否误导及实际加载链。若要评估已加载后遇到范围外请求的行为，另设有真实前序加载记录的会话，要求按入口直接交回调用方，不指定接管技能。两种场景分开报告，不能预载正文后把它算作负向触发测试，也不能仅凭整段宿主回答认定本技能接管。

同类语义义务仍保留在各题 `expected_output`：题5区分编过与修复、处理范围外分支；题8核版本
适用条件；题9核功能契约；题12/14/15/16分别核配置归因、符号定义、前序产物和实际调用域。
删除原句禁项不删除这些义务；明确采纳错误建议的回答即使包含所有主题词，语义判定仍为失败。

本集的 `should_trigger: false` 必须结合完整会话中的加载记录判断。若运行器不支持此文件的
`skill_trigger` 模式，需使用能记录实际加载行为的宿主适配流程，不能直接当作 text eval 执行，
也不能把负例改成回答里不出现技能名的检查。

## 自然触发运行协议

1. 固定宿主、模型、技能包版本、可见技能集合和选择配置，记录每例的运行次数。正常技能发现可见
   名称与 description；不要提前加载本技能正文，也不要在所有 prompt 前强制添加技能调用指令。
2. 每例使用独立会话，避免前一例的技能加载状态影响结果。将非空 `context` 作为本例的既有对话
   背景，再提交 `prompt`；只向选择流程提供这两项，隐藏标签、理由、分类和带正反含义的 ID。
3. 保留宿主原始会话与技能加载轨迹。优先用原生激活事件；宿主若没有该事件，须说明如何根据实际
   SKILL.md 加载记录判定。仅有回答文本、脚本名称或命令输出不构成技能加载证据。
4. 对每例记录实际是否加载、对应事件或记录位置、期望标签及是否一致。缺少可观测的加载记录、
   会话中途失败，或宿主默认预载全部技能正文时，标记无法判定，不把记录缺失计为未触发。
5. 正例分别统计命中与漏触发，负例分别统计正确排除与误触发；无法判定和未运行数量另列。
   报告必须保留全部案例及每次运行的分母，不能仅报告成功项。回答质量和实际编译修复另报。

正例中“需要更多信息”与正确触发可以同时成立；负例中回答分流正确与误触发也可能同时发生。
上下文已经明确转向运行或性能任务时，不应仅凭历史编译错误维持触发。

本文件只规定后续行为评测方法，不启动宿主、访问网络或调用模型。发布包的数据校验不提供
实际激活事件，也不证明触发正确率、编译修复率或宿主能力无回归。

## 修复质量的行为复核

回答评测中的 `expected_output` 是评审依据，不发送给被测模型；`skill_activated` 只检查加载，
不会自动验证回答中的修法或真实补丁。`contains` 也不能证明命令实际执行或状态解释正确。
评测者要对照提供的声明、调用方、参数和原始日志，逐项核对候选决策及结论的证据范围；
没有此项语义复核时，只能报告激活或结构检查结果。

将回答场景制作成工程行为用例时，保留会改变正确决策的相反条件：值对象、设备结构体指针与序列化
缓冲区，局部可见性错误与真实生成ABI歧义，有效比较与输入失败，后台未完成与完整完成收据，指定
实现与允许替换。改换文件名、字段名和布局组合，防止依赖熟悉符号作答；名称变化本身不计为新机制。
独立会话只接收任务、原始工程和日志；评审标签、参考答案及其他运行的修复补丁对它不可见。

每例按四项分别给出状态与证据位置；不能用一个总体通过字段代替这些判断：

| 评价项 | 核对材料与判据 |
|---|---|
| 实现约束 | 对照用户要求审查最终diff、声明和消费链；指定dtype、布局、标量/向量或调用路径须保留，已授权替换则按授权后的语义验收。`contract_intact`或任务文件摘要未变仅说明该文件完整，不证明源码符合要求 |
| 必要目标 | 核原配方、架构、全部必需目标及产物，证据应绑定最终源码、相关依赖和有效配置。一个目标成功、旧产物或后台启动退出0不能代替完整构建 |
| 必要验证 | 根据任务及补丁影响选择数据解释、状态、边界或运行比较；分别记录输入组合、真实执行、比较结果和完成状态。未做可选运行不判编译失败；必要验证缺失则不能判任务全部完成 |
| 陈述准确性 | 最终回答应与证据覆盖相符，区分编译、实现审查和运行结果。输入读取失败、零元素处理或设备错误不能被末尾成功文本/退出0覆盖；旧比较记录须核是否仍适用于最终产物 |

回答场景只能检查对已给事实的决策与陈述，不能据此报告补丁成功率。工程行为验收要读取实际最终
diff、原目标构建、数据/设备执行与比较记录，不把回答承诺、提到页面或工具调用数量当作执行证据。
采用不同但等价且满足要求的修法，应按同一证据标准接受，不要求复述参考回答的词句。

流程评价从**首次编译前**开始：声明、消费方与任务要求已经支持局部修法时，应修改并取得原配方的
下一条证据；存在真实生成、版本或ABI歧义时，应提出能够区分候选的具体未决问题并查证。不得按
调用次数强迫修改或停止必要调查。脚本按入口的足证快路径、诊断触发与复用规则选择，不把知识页、
报告文件作为每题必经步骤。入口已能区分Tiling表示时可直接核源码；仍有缺口才展开相关资料。
知识使用评价关注是否解决当前问题，不奖励单纯增加读取或协作次数。

### 结构化诊断的实际触发

单独记录技能加载与诊断执行：加载正文、回答里提到脚本或任务列表写“诊断”都不算已运行。
默认已有日志诊断的快路径例外，必须由**当时已有**的首错、有效声明/使用方、原配方和保留契约的
局部修法支持；不能用长时间调查后取得的事实倒推最初跳过诊断合理。工具故障须有实际失败记录，
不能将没有调用统一解释为工具不可用。

| 行为分支 | 审查依据 |
|---|---|
| 足证快路径 | 当前证据已支持局部修改，无影响修法的歧义；随后执行或复用适用的原配方验收 |
| 执行诊断 | 实际命令/工具事件、完成状态与诊断产物对应；首诊使用已有日志，未无故追加探针或构建 |
| 复用诊断 | 能指向同工程、目标与问题状态的已有结果，并解释新证据未使其失效 |
| 调用受阻 | 有命令失败、缺依赖或权限证据，记录未取得的能力，继续允许范围内的取证而不绕过保护 |
| 应触发但未执行 | 初读后仍存在影响修法的歧义而继续广搜/猜改，或直接修复首次验证仍报同一首错却未诊断，也无适用结果可复用 |

这些是评测记录类别，不是诊断CLI新增字段。诊断成功输出但无有效定位、建议被源码证伪，均须照实
记录；不能因脚本执行了就算修复质量提高。结合实际缩小的定位范围、被纠正的假设、原目标编译、
实现约束与必要验证分析收益，同时统计无新增证据的重复诊断或重复构建。必要的调查与验证开销
可以保留，但“更贵”和“使用更多工具”都不是质量收益的替代指标。

证据复用既要检查已有记录是否完整，也要检查是否仍适用。构建或运行尚在进行时继续查询同一任务，
不因启动成功就宣告完成，也不自动开第二个重复任务。已有最终状态、完整目标及退出收据时可以复用；
源码、相关依赖或有效配置改变后，补受影响范围的验证。路径名称不同本身不要求重编，主源摘要相同
本身也不足以证明生成输入和依赖未变。完整失败日志已经足够时，不为改变输出筛选方式再编一次。

开销分析绑定实际用途：新增必要目标、排除真实API歧义或完成有效比较，可以支持质量收益；无效
输入重跑、错误目录/设备号、重复搜索和收据缺失造成的返工分别记录。缺少 `file`、`npu-smi` 或某个
物理节点，不足以断言无设备；必要运行应核本进程可见设备、实际vendor和当前输入。更多运行次数
不代表覆盖原输入集合，更多token也不自动代表更严谨；成本降低若来自少做验证，应注明覆盖变化。

材料对照题（45–52）分别检查足证/未决表示、有效/无效比较、进行中/可复用完成证据、
指定/授权实现。它们用于维护决策规则，不能单独证明实际工程的修复质量改善。量化行为收益
仍需固定宿主、模型、技能版本及验收条件实测，并报告全部运行和未确认项。

材料对照题（53–64）补充搜索呈现/范围、可配置与固定目标、参数实际解析、失败查询、存储与
计算精度、tile容量、宏展开、配置内动态加载及依赖副作用。除判断修法，还核其证据边界：
静态数据契约冲突不能写成已复现运行越界；无害清理不能记为额外修复bug；更多目标编译不能
替代当前数据路径验证。输入题目给出明确前提用于检查决策，真实工程中仍须从日志与源码取得这些事实。

材料对照题（65–70）检查足证快路径与默认诊断、首次修复仍同错、同状态复用与新问题、实际工具
故障、未知分类及已有日志复用。它们只检查决策；真正触发率须按上述实际调用事件统计，不靠
回答出现脚本名、SKILL加载或静态数据测试通过推断。测试任务不额外强迫调用某个脚本。

## 数据校验命令

在技能目录运行：

```bash
python3 -m unittest discover -s tests -p test_trigger_evals.py
python3 -m unittest discover -s tests -p test_evals.py
```

触发数据测试检查字段、唯一标识、输入去重、布尔标签及正反标签均存在，并拒绝重复JSON键；回答
数据测试检查schema、引用技能与参考答案的文本断言一致性。它们不判断模型行为，不替代对案例
理由、相反条件及语义预期的复核；仅有激活断言的题目尤其不能将自动断言通过计为修复质量通过。
