# cann_error_code — 编译阶段专有错误码取证

## 诊断信号与级联消歧

适用于构建日志中出现六位字母数字错误码（如 `E...` / `W...` / `I...`）的场景。先判断错误码在日志中的因果位置：若前文已有明确的源码编译错误、缺头、链接失败或 CMake 配置报错，尾部错误码通常是打包器/`opbuild` 的级联汇总结果，应优先定位并修复前序真实首错；仅当错误码本身即为最早阻塞信号时，围绕该错误码展开取证。

## 本地确定性取证动作

1. **提取完整上下文信封**：保留原始错误码、产出组件名称、所处构建阶段、关联输入文件及命令退出码，不截断前后相邻诊断行。
2. **核查本地构建配置与产物前态**：用 `run.py inspect --question build --build-dir <构建目录>` 与 `--question environment` 核实触发该错误码的工具命令、输入原型/核文件及当前 CANN 版本。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| 错误码精确释义、触发条件、所属组件及编译期排障步骤 | cannbot-knowledge `knowledge-query` 技能 | 传入完整错误码、组件、CANN 版本与构建阶段，读取正文及来源并对照本地构建参数 |
| 错误码指向特定算子注册或核函数 API 参数契约违例 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 核对本机活跃 SDK 对应接口声明与当前源码实参 |

## 契约保护红线

本包不内置静态错误码字典，严禁凭错误码前缀臆测修法、套用过期版本解释，或将独立运行期故障强行当作编译修复处理；检索零命中时如实保留待核缺口，详见[知识协作契约](../cannbot-contract.md)。
