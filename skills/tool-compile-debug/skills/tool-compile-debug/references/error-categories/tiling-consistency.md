# tiling_consistency — Host↔Kernel 共享 Tiling 数据契约取证

## 诊断信号与级联消歧

常见信号包括 Tiling 相关类型的 `no member named`、`unknown type name`、解包调用不匹配或结构体初始化元素个数不符。先排除缺失核心头文件引发的级联报错（转 [header-missing.md](header-missing.md)）；同时区分报错位置是手写共享头、Host 注册源码还是构建生成的中间头，不单凭报错落在 Kernel 文件就断定只改消费侧。

## 本地确定性取证动作

1. **串联生产→传递→消费全链**：用 `run.py inspect --project <工程根> --file <失败文件/关联头>` 读取定义与使用点，串清 **Host 构造或填充的数据 → 启动实参 → Kernel 形参类型 → 字段读取表达式**。
2. **识别本工程既有传递机制与字段位宽契约**：核实当前工程采用按值结构体传参、设备全局内存指针传递、共享裸结构体还是 Host 注册宏与生成头解包；在既有机制内对齐字段名、类型位宽、顺序与数组长度，不跨机制强行改写。某字段报 32/64 位冲突时，对照同块相邻字段位宽、Host 生产侧算术及各架构 Kernel/UT 消费侧用法，在确认上游 64 位契约后恢复被窄化的 64 位字段定义，不盲目在生产侧做截断强转。若按值传递已由 Host 实参与 Kernel 形参共同证实，直接访问形参字段，不伪造同名解包宏。
3. **核对多分支与生成链**：涉及分支选择时核对 Host 设置与 Kernel 条件分支的键值一致性；涉及生成头时用 `run.py inspect --question build --build-dir <构建目录>` 核对生成输入、输出路径与包含顺序，比较生成差异须在独立临时目录进行。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| Tiling 注册宏机制、序列化字段约束、生成链路或切分约定不明 | cannbot-knowledge `knowledge-query` 技能 | 读取卡片正文与适用版本，核对本机 SDK 中相关宏定义及当前构建生成的实际头文件布局 |
| 解包辅助接口、Host 上下文 API 或关联类型签名不确定 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 核对当前 SDK 头声明、形参地址空间限定及本工程实际调用层 |

## 契约保护红线

保持原有数据传递方式、字段语义、对齐属性与算子外部原型契约；不因修复内部 Tiling 字段而擅改算子输入/输出描述，不用指针强转掩盖值与设备地址差异，完成后沿原构建配方验证全部目标。
