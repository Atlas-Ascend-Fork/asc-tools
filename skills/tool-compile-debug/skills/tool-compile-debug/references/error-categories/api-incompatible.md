# api_incompatible — API 声明可见性、版本演进与门控取证

## 诊断信号与级联消歧

常见信号为命名空间内 `no member/template/type named`、未声明标识符、实参个数不匹配或弃用告警。先区分工程自有局部符号与 SDK 接口：普通局部变量拼写错且类型语义一致时可直接局部修正；但命名空间或模板接口上的编译器 `did you mean` 近名建议可能指向不同计算语义，绝不能未经核验直接替换。

## 本地确定性取证动作

1. **核实调用点与有效编译命令**：用 `run.py inspect --project <工程根> --file <失败文件>` 与 `--question build --build-dir <构建目录>` 确认调用所在函数域、包含链、宏定义及实际 `--npu-arch` / `SOC_VERSION`。
2. **检索本机活跃 SDK 声明与门控**：用 `run.py inspect --question environment` 确认当前工具链路径与精确版本，在活跃 SDK 头文件目录（解析符号链接后）检索目标符号声明、所在公开头及外围条件编译宏，区分“缺少对应公开头入口”“目标架构宏门控未开”与“当前版本签名变更”。
3. **生成待核问题**：存在未决符号契约时可用 `run.py inspect --question knowledge --symbol <符号名>` 整理结构化查询要素（该命令仅生成问题，不代表已执行查询）。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| 目标版本 API 精确声明、所属公开头、参数契约及支持的目标 SKU | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 读取正文与声明资源，在本机活跃 SDK 头文件中核对精确函数签名与条件宏门控 |
| 跨版本接口演进、废弃替代路线或架构支持差异说明 | cannbot-knowledge `knowledge-query` 技能 | 核对卡片标注的 CANN 版本适用域、旧/新参数语义映射及当前任务目标约束 |

## 契约保护红线

检索零命中只覆盖已查范围，不构成“接口不存在或可删除功能”的证据；严禁靠更换目标 SoC、删除核心计算调用或只改函数短名却忽略参数语义差异来拼凑编译通过。
