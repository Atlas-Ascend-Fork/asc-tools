# kernel_compile_error — 设备调用域语言约束与接口取证

## 诊断信号与级联消歧

适用于已确认落在算子**设备调用域**的编译报错，包括设备函数调用未限定辅助函数、设备侧禁用 C++ 特性（如异常/RTTI/动态容器）、全局内存地址空间（`__gm__`）转换不匹配、设备专用作用域循环约束或内部静态断言触发。先按[调用域判定](README.md#host与kernel的判定依据)确认真实执行域；若实质为 API 签名、模板重载或 Tiling 字段错配，分别转 [api-incompatible.md](api-incompatible.md)、[template-error.md](template-error.md) 或 [tiling-consistency.md](tiling-consistency.md)。

## 本地确定性取证动作

1. **核实编译单元实际配方与限定符**：通过日志或 `run.py inspect --question build --build-dir <构建目录>` 核对失败单元的编译器参数与目标架构；用 `run.py inspect --file <失败文件>` 检查报错函数与被调辅助函数的限定符、头文件包含及宏分支。
2. **核查地址空间与类型可见性**：涉及 `__gm__` 指针初始化或解引用报错时，核对生产方传入的地址类型、真实元素类型与缓冲区绑定方式；涉及基础标量/向量类型或数学函数未声明时，核对公开头入口与设备执行域（标量计算 vs 向量指令 API），不盲从编译器的近名类型或 Host 标准库函数建议。
3. **核查控制流与静态断言原式**：展开报错行关联的源码与 SDK 静态断言原文，核实循环变量值域覆盖、队列/缓冲初始化形式与流水同步配对。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| 设备侧缓冲/队列/同步/数学 API 重载形式、参数结构体成员及目标约束 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 读取正文并对照本机 SDK 头文件中的有效声明、构造方式与静态断言条件 |
| 设备侧 C++ 语言子集限制、地址空间规则或内核编程排障模式 | cannbot-knowledge `knowledge-query` 技能 | 核对适用版本与目标架构，确认替代写法保持原有元素范围与计算语义 |

## 契约保护红线

严禁给依赖 Host 系统资源的逻辑强加设备限定符、靠强转掩盖物理存储类型差异、截窄循环变量导致元素遗漏，或删除报错语句/同步原语换取假通过。
