# compiler_limit — 跳转跨度、模板深度、资源断言与优化敏感取证

## 诊断信号与级联消歧

常见信号包括后端跳转立即数越界（`out of jump/jumpc imm range`）、模板递归实例化超深、分块/片上存储容量静态断言触发，或不同优化等级表现不一致（`-O0` 通过而 `-O2`/`-O3` 失败）。区分**编译器显式报出资源/跨度限制**（本类）与**编译器进程异常崩溃**（转 [compiler-internal.md](compiler-internal.md)）；触发容量静态断言时先按[模板资源约束](template-error.md#tilestage和容量约束要一起满足)核实实例参数，不直接归咎于编译器限制。

## 本地确定性取证动作

1. **定位膨胀源或断言表达式**：用 `run.py inspect --project <工程根> --file <失败文件>` 检查报错函数的分支规模、循环展开编译指示、递归模板终止条件，或静态断言涉及的分块尺寸、流水级数与对齐计算式。
2. **按需执行同配方编译探针**：仅在需验证优化等级敏感性时，在隔离环境对同一翻译单元对比原命令与不同优化选项的编译表现；严禁把降低优化等级的规避结果冒充为“原构建配方已通过”。
3. **结构化收敛代码或分块规模**：针对跳转越界拆分超长函数或收敛编译期完全展开；针对容量断言在不改变外部功能契约前提下调整满足目标规格与对齐约束的分块/流水参数。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| 目标芯片片上存储规格、编译期容量约束、指令跨度限制或分块调优准则 | cannbot-knowledge `knowledge-query` 技能 | 读取卡片正文与目标平台适用条件，核对本机 SDK 头文件中对应的规格常量与断言定义 |
| 关联高阶模板/搬运 API 的分块形参约束与流水配置要求 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 对照本机活跃 SDK 模板声明、默认参数及 `static_assert` 原文 |

## 契约保护红线

严禁注释或放宽 SDK/模板容量断言、删减业务分支、擅自篡改原任务要求的优化配方或更换目标芯片来规避限制；涉及边界形状或流水复用的改动须在闭环内完成验证。
