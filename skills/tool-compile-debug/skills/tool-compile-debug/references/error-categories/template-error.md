# template_error — C++ 模板推导、重载决议与类型约束取证

## 诊断信号与级联消歧

常见信号为 `no matching function`、`call is ambiguous`、模板实参推导/替换失败或 `invalid conversion`。保留首错及完整 `candidate` note 链：区分**模板参数推导冲突**（同一模板形参在不同实参位推出不同类型）与**非推导形参的隐式转换/引用绑定失败**（如非常量左值引用无法绑定临时值），不笼统断言“模板不支持转换”。

## 本地确定性取证动作

1. **精读首错与候选声明**：按日志指向的行号或 `run.py inspect --project <工程根> --file <文件>` 读取调用点实参声明及本地 SDK/工程候选模板定义，核对拒绝原因（实参个数、类型、常量性、地址空间或目标宏排除）。
2. **消歧 32/64 位推导与指针/张量位宽冲突**：遇 `deduced conflicting types`（如 `int`/`uint32_t` 与 `long`/`int64_t`/`uint64_t`）或 `GlobalTensor<T>`/`__gm__` 元素位宽不匹配时，严禁未经核对把头文件声明当真源而在调用点套窄化 `static_cast`！必须核查同结构体相邻字段位宽、上游生产计算表达式、其他架构分支/Kernel 消费侧类型、格式化输出占位符及算子原型 dtype；按已证实的 64 位或 32 位契约决定恢复声明位宽还是修正调用侧。
3. **贯通混合精度数据流与公共分发边界**：涉及存储、计算、累加与写回类型时，沿 Host 缓冲字节分配 → Kernel 元素解释 → 转换/计算 → 最终写回核对类型链路；实例装配违背契约时修实例侧，公共库分发头漏掉合法类型组合时对照同文件相邻特化补齐，严禁篡改调用方外部输出 dtype 绕过缺失分支。

### tile、stage和容量约束要一起满足

仅当报错或补丁涉及分块、流水级数或容量静态断言时执行：将失败断言代入当前实例参数，同时核对形状整除/对齐关系、同存储区并发存活缓冲字节数（按目标 SDK 实际规格核实，不跨架构套用常量）及循环同步配对，不靠删除 `static_assert` 或切换无关调度路径制造通过。

### 返回值与引用参数的契约差异

仅当在返回值重载与引用/指针形参重载间切换时执行：读取当前 SDK 声明及必要实现，核清该引用形参是由被调函数完整初始化输出，还是要求调用者预先分配并跨函数传递有效资源句柄与生命周期；跨函数声明同名局部对象不会共享底层状态，严禁用空对象或赋零掩盖未初始化句柄。

## 契约保护红线

严禁删减功能参数、窄化截断数值域、强转不兼容指针、放宽公共模板断言或违背任务指定的标量/向量实现路径；补丁涉及未决状态或尾块风险时在闭环内完成针对性验证。
