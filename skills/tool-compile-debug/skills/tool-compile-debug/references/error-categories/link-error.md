# link_error — 符号闭合、链接约定与库依赖取证

## 诊断信号与级联消歧

常见信号为 `undefined reference to`、`ld.lld: error: undefined symbol:`、`cannot find -l...` 或配置/生成阶段加载共享库时报未解析符号。先核前序编译或代码生成阶段是否被跳过或半途失败；区分**构建期静态/动态链接失败**（本技能范围）与**独立运行期动态加载器环境路径缺失**（核清编译产物无误后交回调用方）。

## 本地确定性取证动作

1. **锁定失败链接命令与输入集合**：用 `run.py inspect --question build --build-dir <构建目录>` 或原始构建日志提取完整链接命令行、参与的 `.o`/`.a`/`.so` 列表、库排列顺序及 `-L` 目录。
2. **交叉比对请求符号与实际导出符号**：按当前工具链使用 `nm -C`、`readelf -Ws` 或目标文件检查工具，逐项核对未解析符号的命名空间、形参类型/引用/常量性、可见性属性及 C/C++ 名字修饰约定。涉及核函数启动封装或生成入口时，优先核对生成物是否编译链入及共享生成头声明，不盲目给手写原型套 `extern "C"`。
3. **核实库搜索配置**：对 `cannot find -l...`，核查工程 `CMakeLists.txt` 的导入目标、`target_link_libraries` 与目标级链接目录，不把修改运行期 `LD_LIBRARY_PATH` 当作构建期 `-l` 查找失败的通用修法。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| SDK 公开接口对应的归属库名、链接目标或入口封装约定不明 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 核对本机活跃 SDK 库目录下的实际 `.so`/`.a` 文件与导出符号表 |
| 算子工程 Host/Device 混合链接机制、CMake 链接宏或符号导出排障 | cannbot-knowledge `knowledge-query` 技能 | 对照本工程构建脚本与实际链接命令行参数验证 |

## 契约保护红线

严禁靠删除入口调用、编写空函数体/桩符号（stub）或剥离承担注册与初始化职责的目标库来消除未定义符号报错；修复后须沿原配方跑通完整链接与下游生成入口。
