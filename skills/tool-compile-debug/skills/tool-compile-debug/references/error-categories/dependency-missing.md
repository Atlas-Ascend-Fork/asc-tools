# dependency_missing — 生成头、包含目录与跨目标依赖取证

## 诊断信号与级联消歧

本页为跨阶段复合指引（主分类常落于 `header_missing`、`cmake_config` 或 `package_error`），针对消费点所需头文件、中间源码或前置目标未就绪的场景。报错文件名（如 `*_tiling.h` 或 `auto_gen_*`）不能单独证明文件必由工具生成——须按本工程实际目录与构建脚本区分**手写共享文件错位**与**构建期生成产物缺失/失序**，并与 [header-missing.md](header-missing.md)、[schema-consistency.md](schema-consistency.md) 协同判读。

## 本地确定性取证动作

1. **追溯文件权威来源**：用 `run.py inspect --project <工程根> --question build --build-dir <构建目录>` 及工程构建脚本核查缺失文件在源码树中是否存在、是否由自定义命令/生成器产出，以及输出目录与消费方 `-I` 搜索路径是否对齐。
2. **恢复生成→消费依赖序**：确属生成产物时，先排查生成步骤自身的失败日志；若生成成功但消费目标抢跑或找错目录，补齐显式目标依赖（如 `add_dependencies` / `DEPENDS`）或生成物导出目录，不添加整棵 SDK 内部路径掩盖路由问题。
3. **隔离比对陈旧生成物**：怀疑生成代码过期时在源码树外的独立临时目录执行生成比对，严禁直接覆盖用户手写算子实现。

## cannbot-knowledge 查询路由

| 未决领域问题 | 宿主加载技能 | 返回后本地核对项 |
|---|---|---|
| 算子工程代码生成流程、打包生成目录结构或跨目标依赖约定不明 | cannbot-knowledge `knowledge-query` 技能 | 核对本工程实际使用的构建模板、生成器命令行与产物落地路径 |
| 依赖的 SDK 公共头或算子库导出接口位置不确定 | cannbot-knowledge `ascendc-api-knowledge-query` 技能 | 核实本机活跃 SDK 实际目录结构与公开包含入口 |

## 契约保护红线

未经核实消费关系与隐藏副作用前不删除引用；严禁为绕过生成依赖而手造残缺桩文件，或用全量重生成覆盖工程已有的手写核心代码。
