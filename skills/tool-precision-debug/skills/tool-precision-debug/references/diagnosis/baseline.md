## 确认精度比对标准

精度通过标准和参考结果由用户需求或项目已有测试给出；本 Skill 核对其实际执行，不制定通用标准或阈值表。信息缺失时先查看项目需求、比较器和 golden 生成入口，仍不明确的部分请用户补充。

项目已有明确验收要求和 evaluator 时，先按现有入口复现。需求与比较器不一致时说明具体差异，不为了让失败样例通过而切换判据。

记录本次采用的标准来源、evaluator、阈值、特殊值规则和有效区，核对实现是否覆盖所选标准的完整判据。例如浮点标准可能同时要求逐元素容差、通过元素比例和最大绝对误差上限，仅复用 `rtol`、`atol` 的辅助比较不一定等价。有疑点时按下文[校准 evaluator](#校准-evaluator-的实际判据与算术)核对。

沿用已有验收报告；需要定位时，按输出、轮次或观察点整理判定，并补充错值坐标、分布和位模式。这些观察可与工程验收同时使用。逐元素全部通过与“通过比例＋误差上限”的判据可能双向不同，正式验收按项目规则判断。

调用项目比较器时，加载本次真实输出与参考数组，使用项目要求的参数；比较前的类型转换可能改变结果，内置示例只用于理解调用。需要补充局部参考时对齐实际计算语义，不以辅助参考替换项目 golden。原始位比较和随机分布检查分别见下方对应章节。

比较依据尚未核实时，仍记录现有 evaluator 实际返回的 PASS/FAIL，并说明待确认的部分；暂不据此认定算子正确或错误。比较有效后，通过结果也只覆盖本次输入和所采用的判据。

### 随机输出：边际分布与序列要求分开验证

若输出语义确实要求随机性质，先把项目要求拆成范围/边际分布、顺序或跨次依赖、seed/状态推进及可重复性等实际要求；确定性算子在固定输入下偶发错值，仍应先按重复性和设备数据流问题定位，不能因为“结果会变”就改用随机分布验收。

同一批数值排序前后的经验分布完全相同；重复返回上一批结果，也可以保持每批边际分布不变。因此只看每批经验分布、均值或方差的 evaluator，无法单独区分这些变化。若约定要求顺序或跨次独立，用排序、整批复用或状态不推进等受控错误检查 evaluator 是否对相应要求敏感，并按约定增加能观察该要求的验证；约定允许固定 seed 重放时，重放本身并不是失败。这里的反例只说明观察能力，不证明原始序列随机、独立或满足任何统计阈值。

冻结方案实际使用的参数，如实际样本数、批次数、输入/seed 身份、分布参数、检验实现、显著性水平和批量判定方案，并核对参数确实传入了每一层；无需显著性检验的要求不强加 alpha。单次检验仍用内部默认 alpha、批量汇总却按调用方 alpha 计算阈值，或公式使用的批次数与实际执行次数不同，都会让报告与预声明方案不一致。阈值、复测/停止规则由项目方案事前决定；不能从固定通过率倒推接受标准，也不能反复重测直到得到一次通过。

统计通过只能报告当前样本在选定方案下未触发拒绝条件；不应改写成分布已被证明正确。缺少独立性要求的敏感证据、真实样本或可靠检验实现时，明确未验证的部分，不能用边际指标代替这些验证。

## 数值相等与逐位一致

按每个输出已给定的项目判据比较。约定明确要求与参考按原始位模式一致时，任何有效元素的位差都判失败，包括 `+0/-0`、NaN 符号和 payload；数值相等或双 NaN 类别相等不能抵消这些失配。只有函数名或报告字段写着 `exact`/`bitwise`、实际判等语义尚未定义时，才需进一步核对特殊值规则，不能因此将已明确的要求重新列为待定。

已有可信 evaluator 直接复用；需要补充位模式观察时，核对双方 dtype、布局与有效区，再读取原始编码比较，保留代表位置的十六进制位模式。若已知位差违反明确约定，报告约定失配及现有 evaluator 的实际结果，缺失的其它位置或编码另列待查。项目明确采用数值零相等或双 NaN 判等时，按该规则验收，并将它与严格原始位比较分开说明。

双 NaN 只说明类别相同，不证明符号或 payload 相同，也不证明它们不同；把已确认的位差与尚待读取的编码分别报告。现有 evaluator 返回通过也不能反推它采用了哪种特殊值规则；要解释这一通过，需有实际比较逻辑或校准结果作依据。

最终输出逐位一致不自动要求内部计算步骤相同。项目另有求值顺序要求时按其验证；怀疑归约或特殊值导致位差时，再查[归约顺序](../patterns/mechanisms/accumulation-order.md)或[特殊值](../patterns/mechanisms/special-values.md)。

## 确认比较对象与有效区

actual、golden 和 evaluator 必须对应同一输出语义，包括 dtype、layout、逻辑 shape、物理存储、有效范围、容差和特殊值规则。把逻辑、分配、搬运、计算和有效输出元素数分开核对；只有原有要求已排除 padding，才可将它屏蔽，不能因为 padding 失配就事后缩小比较范围。

多输出分别记录判据和结果，并展开整体 PASS/FAIL 的组合关系。仅当整体判据确实是逐输出条件的合取时，才能从某项通过推断剩余失败属于其他输出；若还有跨输出约束，需要单独观察。

判断执行是否成功、输出是否来自本轮产物，按[现场与产物核对](reproducibility.md#冻结失败现场)确认。返回 0、构建成功或报告生成都不能单独证明比较有效，更不能证明精度通过。缺少可信 oracle、有效区或判据时，保留未知项并继续收集证据；不要用辅助工具的默认设置替代项目验收。

## 校准 evaluator 的实际判据与算术

当报告出现“原值不同却通过”“所有元素满足容差却整例失败”，先用小输入校准 evaluator，再定位 Kernel。把实现真正执行的判据逐项展开：逐元素比较、允许失配比例、最大误差上限、特殊值、有效区、多输出聚合及各项的 AND/OR 关系。函数名、报告中的 `bitwise` 字段或一行容差公式不能证明实际语义。

| 反例/对照 | 要核对的边界 |
|---|---|
| 相同数值、不同 dtype；`+0/-0`；相同与不同编码的 NaN | 数值相等、NaN 类别等价和原始位一致是不同判据；先确定约定，再验证对应模式 |
| `uint64` 最大值与有符号 `-1`；大整数的相邻值 | 比较前转窄、转符号类型或转浮点是否把不同原值合并；差值/绝对值是否超出计算类型范围 |
| 全部元素满足逐元素容差，但某元素超过另设的最大绝对误差上限 | 整例实际使用了复合判据；附加上限及允许失配比例也要有约定来源，不能从 dtype 推出 |
| shape 不同、空有效集合、含非有限值的输入 | 应按约定报输入无效或特殊值结果，不能依赖广播、空集合聚合或 NaN 指标偶然得到通过 |

例如 `uint64(2^64-1)` 与 `int64(-1)` 是不同数学整数；若两边先转为有符号 `int64`，可能在比较前已变成同一个值。应保存原始 dtype/位模式，先做不会丢失原值的比较；计算整数误差时再选择能覆盖实际范围的表示。统一转成浮点也不能保证保留大整数低位。用于验收的比较布尔值与便于展示的误差摘要要分开核对：摘要经有损转换显示差值为零，不代表原整数相等。

差值和误差摘要也需要核对计算类型；超出可表示范围或经过有损转换时，保留原始值并说明指标限制，不能用摘要零值覆盖可靠的失配判定。

对每个真正影响 PASS/FAIL 的子条件，尽可能构造一个只触发该条件的失败输入和一个合法对照，保存调用参数与实际结果。若多个条件不能独立触发，说明其依赖关系和尚未区分的部分。复合标准可能是合法项目约定；出现上述分叉时，应先解释它实际验证了什么，不能为了消除 FAIL 自动删掉附加条件。
