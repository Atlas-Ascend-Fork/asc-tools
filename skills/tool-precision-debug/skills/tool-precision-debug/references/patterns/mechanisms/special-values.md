# NaN、Inf、溢出与次正规数

先定位第一个特殊值的产生位置，再区分输入已有特殊值、有限值运算产生溢出、非法域、除零、Cast 饱和以及次正规数处理。最终输出出现 NaN/Inf 不说明最后一个 API 是根因。

## 证据采集

在候选边界保存分类掩码和原始位模式：finite、NaN、正负 Inf、正负零、normal、subnormal。对每个特殊位置追溯参与运算的输入和公式，不用 `nan_to_num` 等清洗先改变基线。

### 先做类别分叉，再算有限值误差

先在代表性失配坐标上区分数值类别，再解释相对误差：

1. `NaN`；
2. `+Inf` 或 `-Inf`；
3. `+0` 或 `-0`；
4. 有限非零，再细分 normal 和 subnormal。

`finite -> Inf/NaN`、`Inf -> finite`、`+Inf -> -Inf` 和 `normal/subnormal -> ±0` 都是类别分叉，应优先定位首个分叉 checkpoint。`NaN -> NaN` 只能说类别可能一致；NaN payload、符号位或任意 NaN 是否算通过，仍由当前 evaluator 约定决定。

保存能定位差异的坐标、计算步骤、actual/reference 类别，必要时附位模式，据此追踪首次分叉。若中间值符合预期而最终编码不同，再查后续 Cast、mask 和写回；输出规范化按项目规定处理。

### 有符号零不能只看十进制打印

`+0` 与 `-0` 的普通打印可能无法支撑判断，应同时保存位模式或 `signbit`。先查符号在哪个 producer 丢失，再观察下游除法、倒数、符号敏感分支或 CopyOut 是否将它放大为可见差异。只有 evaluator 定义符号零等价、且后续数据流不再观察其符号时，才能把 `+0/-0` 归并。

输出都显示为零时，可向前比较首次类别变化的位置，区分正常舍入与更早的缩窄、抵消或特殊值传播。

## 区分实验

1. 在域边界内外取相邻值，区分数学域错误和普通舍入。
2. 缩放输入但保持符号/结构不变，观察首次溢出位置是否按预测移动。
3. 对次正规数使用正常量级对照和位模式对照；只有在输入相同且边界位模式可预测时才讨论 FTZ。
4. 将特殊值传播与有效区分开，排除未初始化 padding 被计算。

### 未选分支也可能污染结果

先计算两支再以 `m*a+(1-m)*b` 混合，不等同于从两支中选择一个值。即使 `m` 恰好是 0 或 1，未选支路的 NaN/Inf 仍可能通过乘零传播。

一个逐步 FP32 的合成例：仅在 `|x|<=1` 时选择多项式 `p=x-x^3/3`，否则选择有限的 `s=sign(x)`。对合法的有限输入 `x=2^100`，若仍在全域计算 `p`，`x²` 已溢出，后续可得到 `p=-Inf`；此时 `m=0`，混合式含有 `0*(-Inf)`，结果成为 NaN，而选中的 `s=1` 本应有限。普通量级 `x=1/2` 是对照。这只解释分支组合风险，不是 Erf 或其他函数的近似公式。

可先保存同一元素的谓词、两支输入与输出类别，再检查合并步骤；不要只看被选支路。若决定使用真实选择或保护未选支路的计算输入，核对具体重载和生成代码，并保证有效支路、阈值两侧与特殊值语义不变。比较模式和 mask 覆盖还需单独验证，不能用算术混合绕过一个疑点又引入极值污染。

### 有限与 Inf 分类边界

稳定改写降低中间范围，不保证与 reference 的有限/Inf 交界完全一致。已知风险很窄时，用输入 dtype 的相邻可表示值检查，重复普通随机回归难以代替这一观察。

例如实数恒等式 `cosh(x)=exp(|x|-ln(2))*(1+exp(-2|x|))`。可先在更高精度下由目标 dtype 的最大有限值 `Fmax` 推导 `|x|≈log(2*Fmax)` 的邻域；不要在目标 dtype 中先算 `2*Fmax`，否则构造输入时就可能溢出。将邻域量化到真实输入 dtype，再沿相邻位模式在合法域内选取两侧对照。

| 观察点 | 要区分的候选 |
| --- | --- |
| `u=round_D(abs(x)-ln2_D)` | 输入、常量量化或减法舍入是否已改变边界 |
| `v=Exp(u)` | 实际 API 的近似与分类边界是否首先分叉 |
| `w=1+Exp(-2*abs(x))`，`y=v*w` | 后续修正项与乘法是否引入最终溢出 |

保留 reference 与 actual 的类别、输入位模式和首个中间分叉；公式只用于设计候选观察，不要求项目采用这条实现。若只有最终有限/Inf 日志而没有中间值，保留多个解释。其他 Exp、缩放和饱和表达式按各自公式重新映射边界，不复制 Cosh 的阈值。

### 有限输入的归约顺序也会改变非有限类别

所有归约输入均 finite，不能排除中间加法溢出；不同的结合顺序可能分别产生有限值、单一符号 Inf 或 NaN。先确认归约入口的原始 FP32 值，再追踪两棵树中第一次溢出及后续传播，不能只查最终 Cast 或输入是否含 NaN。

例如令 `A=2^127`，每步采用 FP32 最近偶数舍入，同一组有限输入的三种求值方式如下。这是可复算的数值模型：

| 求值顺序 | 结果 | 中间原因 |
| --- | --- | --- |
| `(A + (-A)) + (A + (-A))` | `0` | 每对先抵消 |
| `((A + A) + (-A)) + (-A)` | `+Inf` | 首次同号相加溢出，之后减有限数仍为 Inf |
| `(A + A) + ((-A) + (-A))` | `NaN` | 正负两支分别溢出，再合并反号 Inf |

因此应逐坐标比较 finite/NaN/正负 Inf，不能仅比较非有限值总数。若 evaluator 仅在双方 finite 的交集上计算误差，`mere=mare=0` 可能只是没有可比较的有限元素；还要读取 `finite_compared` 和类别失配。原判据对 NaN、Inf 的定义优先于某个通用相等函数。

固定参与元素和初始 FP32 位模式，只改变结合树；或按二进制幂缩小输入作为溢出对照。缩放后恢复只支持范围/顺序候选，不替代原极值回归。FP64 或补偿求和即使更接近数学结果，也可能改变既定 FP32 reference 的类别，不能直接认定它满足验收。参考分派与实例分别见[分层归约](accumulation-order.md#框架参考的分层归约与主尾列分派)和 [GRU bias 案例](../cases/thnn-fused-gru-bias-reduction.md)。

### Normal / subnormal / zero 三点与三阶段探针

对“极小非零变成零”的症状，不要只测一个极小值。在目标 dtype 下构造至少一个明确 normal、一个明确 subnormal 和零；如果涉及符号敏感下游，再对正负分别构造。每个点用目标 dtype 的原始位模式定义，不用十进制字面量或打印位数猜测它属于哪一类。

对同一组固定输入分三段保存位模式：

| 阶段 | 可选择的观察边界 | 首次归零时的候选方向 |
|---|---|---|
| 产生 | 算术 API 或 Cast 的直接输出 | 该生产步的 dtype、舍入、模式或输入范围 |
| 搬运 | 产生值写入后与消费前的相同逻辑元素 | Cast、长度/有效区、布局、同步或 Buffer 生命周期 |
| 消费 | 下一运算的入口与直接输出 | 消费 API 的行为或对已归零输入的放大 |

例如“产生处仍是极小非零，搬出后首次成为 `-0`”先把边界收缩到搬运或其中的 Cast/解码，不足以宣称产生 API 执行 FTZ；还要用 `+0/-0` 位模式、normal 对照和有效区证据排除符号、布局与越界问题。

只有 subnormal 与零分叉、normal 对照仍通过，且首次归零阶段在重复运行中稳定，才提高 FTZ 候选的优先级。这仍不证明某 API 或模式的通用行为；需要当前版本权威文档或精确范围的硬件探针才能将它提升为事实。

FP32 格式能够编码 subnormal；某个中间 FP32 结果是否实际保留，不能从 dtype 名称推断，需由当前 API 模式、位模式观测或权威文档确认。它与最终输出接近零或最终舍入为零是不同命题；不能仅因数值“很小” 主动清零。遇到极小值突然归零时并列核对三类机制：逐操作公式是否已 overflow/underflow、当前版本 API 模式是否规定 FTZ/次正规数行为、源码是否有显式 clamp、阈值或 zeroing。每类都要以首个分叉的位模式和单变量 trigger/control 判断；不要把某次设备观察推广为所有 API、模式或平台的规则。

### 非法域先追 producer

`Log`、`Sqrt`、倒数或其他有输入域约束的步骤首次产生 NaN/Inf 时，先将它的输入与当前 oracle 的同一 checkpoint 分类。如果两边都给出约定允许的特殊值，它可能是正常传播；如果 kernel 独有的非法输入在这个消费者之前已经出现，沿它的 producer 链继续向上追溯。

对理论上应非负却得到微小负值的 `Sqrt` 输入，至少并列保留数值抵消/舍入、错 offset、未初始化读、有效区或同步错误等候选。只在当前算子约定明确规定保护时才测试对应保护；不用通用 clamp 或新增 epsilon 截断 producer 证据链。

## 结论限制

FTZ、特殊值传播和饱和语义依赖 dtype、指令和平台。没有目标版本文档或实测时保留未知，不把 CPU 或其他 NPU 的行为外推。修复不能仅屏蔽特殊值；应处理已确认的首个产生机制并回归正常值与边界值。

改动影响多条特殊值处理路径时，选能暴露同类错误的输入检查相关实现。例如，直接选择零与将 NaN/Inf 乘零可能产生不同结果；修改或撤销保护后，补验受影响部分。

## Oracle 与保护约定

先确认 oracle 在同一输入、dtype 和逐操作公式下究竟产生有限值还是特殊值。实现额外产生 NaN/Inf，与实现把 oracle 的 Inf/NaN 改成有限值，是方向相反的失败。普通相对误差在 Inf 或 NaN 上可能产生假阴性，比较必须先按类别和位模式处理，再计算有限值指标。

epsilon、clamp、减最大值和稳定公式都会影响算子语义。只有当前语义允许、已排除错误统计集或搬运链，并且单变量实验与边界回归支持时才可采用；不能为了让当前样例通过统一添加。对 Norm、Softmax、除法和对数分别冻结保护的位置、dtype 和顺序。

## 次正规数与窄带放大

把次正规数的产生、搬运和消费拆成三个探针，并在正常量级设置对照。若失败只落在很窄的输入带，沿后续乘除或分支计算局部差异的放大条件。FTZ、近似模式和特殊值传播属于版本/平台事实；旧案例观察只用于设计当前环境探针，不能外推为默认行为。

消费端即使只收到零或一个 subnormal 差异，也要问后续大系数、倒数、归一化或分支会否把它放大为最终可见偏差；反过来，最终接近零也不能证明先前中间量已经归零。用同一逻辑元素的 producer、consumer 位模式和局部 oracle 区分这两种方向。
