# Matmul、卷积、Norm 与复合算子边界

复合算子应先拆成可观察的数据边，不直接从最终误差猜测某个高阶 API。至少区分输入布局与搬入、主计算、累加/归约、缩放或量化、激活、搬出以及多核合并。

## 局部 oracle

为每条边建立与实际 layout、dtype 和有效区一致的局部 oracle。Matmul/MMAD 要记录 M/N/K、转置、ND/NZ 布局、输入与累加 dtype、HF32/量化配置；Norm 要分离统计量、归一化和仿射；卷积要分离 im2col/LoadData、Cube 累加和后处理。

## 定位顺序

1. 确认输入搬入后的逻辑矩阵或向量与 oracle 一致。
2. 检查主计算输出的首次分叉，避免被后处理饱和或 Cast 掩盖。
3. 对归约或 K 轴使用长度边界和强消减输入。
4. 对随路量化、ReLU、bias 和输出布局，优先逐项关闭或替换；无法分离的变化按组合干预解释。

## 反向依赖切片与首分叉四问

- **何时查**：最终输出同时可能由搬运、主计算、partial 合并和 epilogue 解释，或全量 dump 成本过高时，从首错输出坐标反向切片。
- **查什么**：只保留能到达该输出坐标的 producer、tile/core、partial 和后处理边，逐边记录 `producer -> consumer`、逻辑坐标、dtype/layout、有效区、owner 与局部 oracle。对 fan-in 边必须验证完整贡献集合，不能用一个正确 partial 代表整个合并。
- **怎么证伪**：根据相邻点的有效比较继续定位：上游匹配/下游分叉时保留该边候选；两者都错则继续向上游；两者都匹配则向下游。不可比的点标 `AMBIGUOUS`；观察虽改变执行条件、但本轮比较仍有效时，保留本轮 PASS/FAIL，并限制对原程序的推断。受控地用 oracle 替换该边输入时，先确认替换生效、被检验关系仍成立，且必要预测有区分力；下游观察与该预测矛盾时，只排除相应的单因解释。
- **避免混淆**：“最早被观察到”不等于“最早产生”，时间顺序也不等于数据依赖顺序。边界跨越 layout、Cast 和同步三种变化时仍太宽；先增加能区分候选的 checkpoint。首分叉落到广播、排序、卷积或 MMAD 后，转相应算子/API 页，不把本页升级为万能根因。

## 机制依赖与遮蔽

同一最终误差可以同时包含搬运、布局、累加、参数、同步和后处理缺陷。先修复或绕过最早分叉后，必须重新建立边界；后面的机制可能此前被全零、NaN 或错误槽位遮蔽。局部 oracle 只证明它覆盖的数据边，不把前一 checkpoint 正常外推到未观察的内部阶段。

## 何时停止展开

全链路 dump 不是目标。只要相邻两个可比 checkpoint 已形成“上游与局部 oracle 一致、下游首次偏离”，且保留下来的候选对下一项单变量实验给出不同预测，就停止继续向无关阶段展开，转入该数据边对应的机制页。若相邻点仍同时跨越布局转换、dtype 转换和同步，则边界还不够窄；优先增加一个能减少竞争候选的观察点，而不是把所有内部张量都导出。

停止展开前确认两点对应同一逻辑数据、有效区及明确的 dtype/layout，采集完整，并有适用的独立 oracle。下游不可比时将该点记为 `AMBIGUOUS`；上游通过不能证明两个点之间所有隐藏阶段都正确。观察改变 UB、同步或 tiling 时，说明与原程序的差别；本轮比较有效仍保留其结果，需要向原程序推断时再核对未插桩基线。选点、状态与成本控制沿用[观察点设计](../../diagnosis/checkpoint-design.md)。

## 绕过后的残差线程

对最早分叉做有效实验或受控绕过后，重新计算整个误差拓扑。只有有效实验兑现了该解释的区分性预测，才能称第一条解释已获支持；单纯绕过只提供边界观察。原症状按预测消失而出现互不重叠的新坏点时，可能是此前被遮蔽的第二缺陷；保留已支持解释和证据边界，为新残差建立独立线程，不用新形态反向否定已经兑现的预测。若旧坏点仍有可信残差，先判断是原线程未完全解释、正式修复不完整，还是补丁引入回归，再决定是否拆线程。

每个线程记录自己的首错边界、假设、实验、修复范围和回归集合。只有后续证据支持同一因果链，且合并不会丢失任一原始边界、Parent、实验和验证状态时才合并线程；最终报告必须分别说明已解决、未解决和未验证的机制。线索拆分与合并的通用判据见[假设与实验](../../diagnosis/hypothesis-experiment.md)。本页方法不携带任何固定 API、阈值或生产根因；强事实继续查询对应版本的官方文档。

优先路由到独立算子说明：Reduce、Broadcast/Transpose、Matmul/MMAD、Normalization 和 Convolution 分别保存数学约定与 checkpoint。本页用于复合链拆分和多机制线程管理，不替代算子公式或版本 API。

高阶 API 的 tiling、workspace、支持 dtype 和产品限制必须查询当前版本的官方文档。生产算子中的用法只能证明一种已观察模式，不能自动成为所有 shape、版本或产品的接口约定。
