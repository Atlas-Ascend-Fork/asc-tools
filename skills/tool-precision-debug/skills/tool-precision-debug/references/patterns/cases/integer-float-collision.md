# 整数进入浮点链：相邻整数碰撞

资料范围：CANN 9.0.0；产品 Ascend910B1；NPU Arch 2201；调用或执行路径 kernel-direct。下述结果仅覆盖列出的输入与执行方式。

这是一个用固定输入说明数值机制的小实验。当离散索引、计数、标签或地址在进入浮点中间量后出现重复命中、相等判断异常或仅大数范围错值时，用本案例先验证“整数值是否已在 Cast 边界合并”。它只帮助定位表示丢失，不能替代当前 API 重载、舍入模式、地址单位和业务范围的确认。

## 示例结果

固定输入探针在 CANN 9.0.0、Ascend910B1/DAV2201、kernel-direct、单 block、256 lane 下比较原始整数与转换后的 binary32 位模式。

probe 对 `2^24-1`、`2^24`、`2^24+1`、`2^24+2` 及负数对应项逐 lane 验收 binary32 位模式。该探针的 256 lane 均无失配、无 GM 哨兵残留，并观察到正负相邻碰撞：`2^24` 与 `2^24+1` 都编码为 `0x4b800000`，`-2^24` 与 `-(2^24+1)` 都编码为 `0xcb800000`。它不验证其它 CANN 版本、SoC、长度、tiling、融合、算子实现或 Cast 重载。

## 最小可证伪案例

将原始整数、Cast 后浮点位模式和下游判断结果同时保存；不能只保存转换后的数值。

| 输入对 | 原始整数是否相等 | binary32 后是否相等 | 用途 |
| --- | --- | --- | --- |
| `16777216, 16777217` | 否 | 是 | 触发：相邻整数发生碰撞 |
| `16777215, 16777216` | 否 | 否 | 边界前 control |
| `16777217, 16777217` | 是 | 是 | 相同原值 control |

若首行在当前真实链路中满足“原始整数不等、Cast 后相等”，而第二行仍保持不同，才提高整数表示丢失候选。若输出约定本就允许 `int32→FP32` 舍入，碰撞本身不是 API 故障；只有当前用途要求逐个整数可区分时，它才是需处理的表示损失。若原始整数已相等、Cast 前地址或比较已分叉，或边界前也失败，转查上游索引、单位、有效区或存储覆盖，不能把现象归为浮点碰撞。

负数和业务实际最小/最大值也要配对。`2^24` 是 binary32 有效精度边界的案例值，不是任意 dtype、量化格式或 API 的通用阈值。

## 局部干预与修复代价

先只让需要逐个整数精确的那条比较、索引或寻址链保留整数表示，保持输入、shape、mask、tile、地址和其它计算路径不变。预测是触发对重新不同，而相同原值 control 仍相等；若结果不变，检查实际产物是否采用以及 Cast 是否真在该边发生。

保留整数链会改变可用的算术、临时存储、接口重载和可能的 buffer 容量。若必须在某一边转换，先按当前版本的精确 Cast 约定核对 dtype、模式、目标区容量和读写生命周期；“同为四字节”或最终再升宽都不能恢复已丢失的低位。

## 回归与结论边界

回归至少覆盖原始失败值、`2^24` 两侧相邻对、正负对、相同原值对，以及当前算子实际会使用的完整/tail 与多 tile 路径。对每组保存整数原值、浮点位模式、第一次分叉 checkpoint 和最终逻辑输出。

Cast 的一般诊断分流见 [Cast、舍入与中间精度](../mechanisms/cast-rounding.md)。
