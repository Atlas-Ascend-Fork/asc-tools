# Partial 统计合并：局部正确不等于全局正确

分块统计、归一化或归约在单块正确、跨 chunk/跨核/尾块才失配时，先把每个 partial 当成有语义的状态，而不是只搬运一个最终均值或局部输出。本页是合成的数学诊断案例；它不规定任何 CANN API、并行树或空输出语义。

## 症状与竞争候选

先冻结可信 oracle 的统计定义、输入/内部/输出 dtype、有效元素集合、分块边界、partial 的存储位置和最终合并顺序。本例选择 Welford 状态 `(count, mean, M2)`；其它合法统计可使用 sum/sumsq 或不同状态字段，必须由当前算子约定给出。单块通过而合并后错，可能是遗漏 partial、把不同长度 partial 等权平均、遗漏跨组偏差项、把空块当作 count 大于零的普通数据，或是同一有效集合在不同树形/合并顺序下的舍入差异。

不要把“结果随 chunk 数改变”直接叫低精度。先确认所有 partial 的有效元素集合及 count 是否正确；集合不同是有效区/地址问题，集合相同而 dtype 或顺序不同才进入累加顺序候选。

## 一个可区分的合并实验

将输入切为两个不等长块，并对每块独立计算状态、直接全量计算状态和当前实现的合并状态。对非空的 A、B，正确合并必须把 count 相加，并按 count 加权均值；二阶中心矩还必须包含由两个均值差产生的 cross term。只把两块均值等权平均，或只相加两个局部 M2，在不等长且均值不同的输入上都会给出可预测的错误。

精确有理数模型的触发器是 chunks `[0, 0]` 与 `[10]`，其 partial state 分别为 `(count=2, mean=0, M2=0)` 和 `(count=1, mean=10, M2=0)`。直接全量 oracle 与正确合并都得到 `(3, 10/3, 200/3)`；错误等权均值给出 `5`，遗漏 cross term 的 M2 给出 `0`。只修均值权重时，M2 仍会错误；只补 M2 项时，均值仍错误，因而这两项干预和各自 checkpoint 是可区分的。

空 partial 应按 count 作为恒等状态处理；其 mean/M2 字段可以依当前实现约定为零或其他占位，只要 count=0 时不被当作普通数据参与合并。模型的单个非空 state 与空 state 合并是 identity control。另一个 control 用等长 `[0]`、`[10]`：等权 mean 恰好为 `5`，却仍需要正确的 M2=`50`；同均值 chunks 的 cross term 则为零，不能区分漏项。尾块与整块使用同一状态合并公式，但各自 count 必须来自实际有效元素；若尾块被当成完整块，先回到 [尾块有效区与旧状态：先证明本轮写入](tail-valid-region-state.md) 审计有效区。

若当前输出要求逐位一致，还要以当前 oracle 的 tree、partial dtype 和最终 Cast 为准。将并行合并改成串行、提高 dtype 或调整 chunk 只能是区分实验：它可能改变舍入点，却不能证明遗漏 partial 或错误统计公式。

## 修复与回归

正式处置前写清每个 partial 的 producer、存储 dtype、count、合并消费者和最终 Cast，并用直接全量 oracle 验证多个不等长切分、空块、尾块及反向到达顺序。修复后同时回归单块与多块；单块保持通过并不能证明全局 merge 已闭合。缺少当前算子对方差分母、空输出、NaN 或精确顺序的约定，保持 `UNKNOWN`。
