# Checkpoint 设计

需要中间观察来区分可疑计算、搬运或数据依赖时使用。本页帮助选择观察位置、准备局部对照，并根据结果推进到具体代码问题；已有可信观察可直接复用。

## 选择位置

先明确本轮需要回答什么，例如“写回前已经算错，还是写回及后续访问时出错”。沿失败输出的实际计算链选择少量候选点，考虑每种观察结果会让下一步检查哪段代码、哪条数据依赖。若不同结果都不能改变调查方向，换一个位置或复用现有证据，不增加无区分力的 dump。

优先选语义清楚、局部对照容易取得、采集成本和扰动较低的位置。按当前疑点参考以下选法：

| 当前疑点 | 可选观察位置 | 希望区分什么 |
| --- | --- | --- |
| 不清楚偏差来自哪段计算 | 已有正常输入与失败输出之间的主要阶段边界 | 哪一段值得继续细查；具备二分条件时再缩区 |
| 计算与搬运、写回难以区分 | 搬运前已就绪的源数据与搬运完成后的对应目标数据 | 源值已经偏离参考，还是传递后才出现差异 |
| Cast 或量化前后出现变化 | 转换前输入与转换后对应输出 | 输入已有偏差，还是转换的参数、舍入或输出表示有问题 |
| 尾块、周期或后续循环才失败 | 实际失败的 tile/轮次及可比的相邻正常区域 | 问题是否随有效长度、分片或缓冲复用出现 |
| 多分支在融合节点汇合 | 相关分支进入汇合节点前的输入及该节点输出 | 哪条输入路径已有偏差，还是汇合计算引入了差异 |

分支按真实 producer→consumer 关系分别检查，不能按源码先后把无依赖的点串成二分链。已有明确候选时，围绕其预测选点；无需先覆盖全部计算节点。

## 对应到本次执行的数据

同一源码位置可能处理多个 core、tile 和循环轮次。由原始失败的逻辑坐标反推执行归属，确定本次观察的分片、轮次、局部偏移和有效切片；前后两个点应对应同一批逻辑数据。涉及归约等跨元素计算时，局部参考还需取得该输出所依赖的完整输入范围。方法见[错误坐标与并行归属](localization.md#解释索引和并行归属)。某个正常 tile 的观察不能代表尚未采集的失败轮次。

用已有报告或简短记录保留源码位置与执行归属、张量的 dtype/shape/layout/有效区、参考依据与比较规则，以及实际输入、运行产物和观察文件的关联。按当前问题补充必要信息，缺项注明，不要求另建固定格式的计划。

观察某阶段的输出时，确认生产者已完成相关写入，且缓冲区尚未被下一轮复用；源码执行到该行不等于异步数据已就绪。就绪性不明时可保留瞬时值调查依赖，暂不据此判断该阶段的计算结果。使用 DumpTensor 输出 Tensor 值时，检查[数据就绪与插桩影响](dumptensor.md#数据就绪与插桩影响)；使用局部模型时按[数值对照](numerical-modeling.md#建立可比条件)确认可比范围。

## 准备局部对照

通用精度标准与 golden 构造方法调用 CANNBOT `ops-precision-standard` 技能查询，已有明确项目要求时优先沿用。每个中间点还需匹配自身的公式、输入、dtype、量化或 Cast 位置、layout 和有效区；归约的轴、累加精度及必要的求值顺序也需对应。具体例子见[局部比较链](operator-modeling.md#从输出类型建立局部比较链)。最终输出的 golden 或容差不能直接套到所有中间张量；没有可靠局部判据时先保留数值和趋势，不自行设阈值判错。

按本轮问题选择参考方式，说明它回答什么：

- **从原始输入推导到该阶段的参考值**：观察截至该点的累计偏差，包含上游误差的传播。
- **将该阶段的实际输入送入独立局部参考实现**：连同影响计算的属性和必要状态，检查本阶段是否产生超出局部判据的差异。该对照通过仍可能意味着上游错误被正常传递，不能据此把此前整段计算标为正确。

两种参考的输入和用途不同，不能混成同一条正常/异常边界。需要区分误差传播与局部新增差异时，见[逐层分析的局部对照](progressive-error-analysis.md#区分传播与新增偏差)。

### 无 golden 时的边界

缺最终 golden 不等于停止观察。可以依据已确认的计算定义构造独立参考，用可手算小例或另一条可信路径核对；也可使用已验证对照、任务给定的中间值或适用的不变量。不要根据 actual 倒推一个能匹配它的答案；复用 Kernel 中可能出错的索引公式或 helper，也不能算独立验证。

说明参考依据覆盖的性质。例如恒等搬运可检查元素映射和值是否保持，shape、范围或守恒关系只能验证各自性质。不变量通过不能证明完整计算正确，也不能替代数值比较来排除整段代码。依据不适用、数据不可比或采集不完整时保留 `AMBIGUOUS`，继续补对照或选择其他观察。

## 判断观察是否有效

存在插桩本身不表示已经改变原始故障，也不能凭一次结果未变就认定完全无影响。新增同步、改变分片、缓冲布局或计算路径时，说明这些干预及其影响；观察到错误位置、幅度或触发条件变化时，核对插桩与原程序的重复性差异。已有适用对照可复用，需要进一步区分时再按 [DumpTensor 方法](dumptensor.md#数据就绪与插桩影响)比较，影响未确认就保留未知。

已知干预改变了关键执行条件，或对照支持原始故障受其影响时，注明受扰动；边界移动时保留原始基线与本轮观察。只要本轮输入、参考和采集仍支持有效比较，就保留本轮 PASS/FAIL，并说明对未插桩程序的代表性限制；无法建立有效比较时记为 `AMBIGUOUS`。

### 结果状态

- `PASS`：该点本次有效比较按声明的参考依据和规则通过。
- `FAIL`：该点本次有效比较按相同规则失败，不要求先证明稳定复现。
- `AMBIGUOUS`：参考依据、采集完整性或比较语义不足，无法判断本次观察；包括扰动破坏比较前提的情况。
- `UNTESTED`：尚未获得观察证据。

稳定、漂移或偶发描述重复观察，不能覆盖单次有效的 PASS/FAIL。状态只覆盖所比较的性质、数据范围和执行实例；某个切片通过不代表整个张量或所有轮次通过。

保留可获得的最大误差、错误位置、有效元素数和特殊值差异，缺失指标保持未知。状态绑定实际观察文件或报告，不能仅凭日志中出现 checkpoint 名称生成，也不能因为最终输出通过而回填前面的 `PASS`。

## 根据结果继续定位

例如调查 `计算结果 → CopyOut → GM 输出`，选取同一失败切片，核对写回前源数据与写回后的对应目标数据。两处的输入、元素映射和采集时点可比时，按结果推进：

| 有效观察或发现的缺口 | 下一步 |
| --- | --- |
| 写回前已偏离可信参考 | 沿该切片的上游输入与计算检查，必要时区分传入偏差和本段新增差异 |
| 写回前匹配参考，GM 对应位置不匹配 | 核查搬运参数、目标地址、后续覆盖及可见性；这还不能证明 CopyOut API 本身有问题 |
| 两点不对应同一批逻辑数据，或就绪性不明 | 先修正坐标、轮次或采集时点，暂不据此排除计算区间 |
| 插桩后原始异常消失或边界移动 | 保留本轮有效结果，核对插桩影响与重复性，不用当前通过覆盖原始失败 |

有观察或源码事实支持具体代码候选时，进入[针对性实验](hypothesis-experiment.md#实验设计)，验证其如何造成原始异常。需要继续缩区时，按[语义二分前提](semantic-bisection.md#前置条件)核对同一依赖链上的可比、稳定端点及局部单调假设，`AMBIGUOUS` 点不能充当正常或异常端点。误差累积、放大或出现 `PASS → FAIL → PASS` 时，使用[逐层分析](progressive-error-analysis.md)。首次可见差异、首次超差和根因分别判断，不必为完成二分而继续加点。

## 控制成本

每轮优先增加能改变下一步判断的观察，复用已有输入输出、采集结果和报告。相同位置、相同方式不再提供有效信息时，按缺口更换观察位置、参考方式或采集手段，不堆叠无用 checkpoint。

多轮缩区时，引用已有工程或官方比较报告，按观察点整理结果，保存到[任务产物目录](reporting.md#任务产物目录)。所选比较器决定各点 PASS/FAIL，首次非零误差与首次验收失败分别观察。真实依赖链、跨轮稳定性和插桩影响需单独核对；参与边界判断的点缺少比较依据、采集背景或扰动影响未知时，先补齐前提，不据此进行二分。

取证结束后移除临时插桩；改过执行源码时干净重建并按原入口回放，如实保留结果，偶发问题不要求每次对照都失败。恢复确认只说明临时改动已清理，修复结论仍需对应正式修改和实际验证。
