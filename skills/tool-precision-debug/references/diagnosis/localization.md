## 整理已有错误

复用原比较结果，先看哪个输出、哪些有效元素失配，再看代表位置的 actual、golden、绝对差和特殊值类别。结合完整数组或已有统计，判断错误是局部、周期分布还是覆盖大部分输出。只有部分日志时保留已有信息和覆盖限制；错误阶段、最小触发条件与稳定性未知时仍可继续分析。

比较口径不清时先查 [baseline](baseline.md)。需要补充位置或局部指标时，分析已有输出与参考数据，保留项目 evaluator 的原判定；辅助逐元素失配不自动等价于项目整例失败。

解释错误位置和统计范围时注意：

- 报告中的首个失配位置需按实际比较器的遍历顺序、数组 shape 和 layout 解释，不代表设备执行时间上最早的错误。
- 报告可能只列出部分异常样本。判断周期或覆盖范围时，应回到完整数组，按适用的逐元素规则统计相应行、通道或区域，不能把少量展示点当成全部错误。
- 按原有输出语义确定有效区。只有有效元素在实际展开顺序中构成连续前缀时，才能截取前若干元素；与 padding 交错时，按逻辑位置选择有效元素，不能事后排除失败位置。

## 按现象选择路线

| 当前观察 | 先做什么 |
| --- | --- |
| 少数位置、某几行或尾部错误 | 将代表坐标映射到实际索引、搬运长度、尾块和有效区，检查对应代码 |
| 错误呈周期 | 对照实际 stride 单位、行边界、tile/repeat 和分片表达式，选能区分这些解释的位置检查 |
| 大部分输出有相似偏移、比例或可解释错值 | 用已有输入和计算关系做[错值反解](#错值反解)，不必先按 core、row、tile 逐级收缩 |
| 固定输入下错误位置或幅度变化 | 按[重复性方法](reproducibility.md#判断稳定性)比较各轮结果，核对生命周期、所有权、同步与运行条件 |
| 只有最终错误，尚不清楚在哪段产生 | [沿数据流](#沿数据流收敛)选择少量阶段观察，区分上游已错还是本段引入差异 |
| 零、近零、NaN/Inf 相关差异 | 先按原规则分清类别、绝对差与参与范围，再回到对应坐标和上游操作 |

这些形态只决定下一步检查方向。周期等于某个 tile 长度、全零或误差很大，都不能直接证明根因。零与近零处同时看原值、绝对差和项目判据，不临时给分母加 epsilon 或自设近零阈值改判；NaN/Inf 先比较类别，避免普通误差聚合掩盖差异。

## 解释索引和并行归属

选一个能代表当前疑点的失配位置，按下面的顺序回到代码：

1. **确认坐标含义**：按比较数组的 shape、layout 和有效区解释索引。若比较前做过切片、转置或去 padding，先还原到原张量位置。
2. **计算实际偏移**：按存储布局求元素偏移和字节偏移，分清 Tensor 起点、维度步长及单位，不把逻辑序号直接当地址。
3. **确认执行归属**：从本次 Host tiling 和 Kernel 索引表达式求相应阶段的逻辑 block/thread、tile 和循环轮次。Dump 文件的核编号需按[记录配对方法](dumptensor.md#对齐观察记录)对应，不能直接当作逻辑 block。
4. **代回实现检查**：将位置与偏移代回相关搬运、计算和写回的地址、长度、掩码及分支；有具体疑点就验证，缺状态时再围绕该执行实例观察。

涉及归约等跨元素计算时，还要追踪该输出依赖的完整输入范围，一个输出坐标不代表一个输入元素。

例如逻辑 shape 为 `(4,6)`，按行存储，每行分配 8 个 float32，末尾 2 个是 padding；比较器读取的是包含 padding 的 `(4,8)` 数组：

| 同一失配元素 | 值或计算 |
| --- | --- |
| 物理数组坐标 | `[2,2]` |
| 物理数组扁平索引 | `2 × 8 + 2 = 18` |
| 紧凑逻辑数组中的序号 | `2 × 6 + 2 = 14` |
| 相对该数组起点的字节偏移 | `18 × 4 = 72` |

若工程明确每个逻辑 block 处理两行，才可进一步得到 `block = 2 // 2 = 1`；其他分派按实际公式计算。本例应选择每行前 6 列参与比较，不能将物理数组按行展开后直接取前 24 个元素：后者包含前几行 padding，却漏掉最后一行有效元素。

按疑点选择错误点、邻点、周期对应点或正常对照，不要求固定样本角色和数量。筛选已有结果中的一个区域不改变原执行；减小 shape、核数或只运行某个 tile 则属于新的诊断实验，需核对分片、输入依赖与触发条件是否改变。

## 错值反解

计算关系明确时，直接用已有输入输出检验解释，无需先遍历空间或增加设备探针：

1. 从实际可达源码提出少量候选，例如参数错位、漏乘、误写中间量或分支错误。数值相似但不可能到达该输出的候选先排除。
2. 用同一套解释预测所选输入和位置的错值、差值或错位，与实际结果核对。保留相关 dtype 和运算语义；依赖舍入或逐位结论时才进一步核对位模式。完整短例见[假设验证示例](hypothesis-experiment.md#一个完整例子)。
3. 若模型曾为匹配 actual 调整过，用未参与拟合的数据或独立观察再区分；已有可信对照可复用，不为每个点拟合不同常量。

多个候选都吻合时，寻找它们预测不同的输入或观察位置。关键 API 行为不明时调用 CANNBOT `ascendc-docs-search` 技能核对；输入不可重建或打印丢失精度时保留缺口，不把近似拟合写成已确认事实。不同 dtype 命中不同表达式时，先核对实际分派与共享代码，再判断是否属于不同问题。

## 沿数据流收敛

需要判断偏差在哪段产生或传递时，沿失败输出反查真实计算链：输入和 tiling 参数如何进入 Kernel，经过哪些搬运、计算、同步及写回。选能改变下一步判断的前后观察点，例如计算后写回前的结果与对应 GM 数据，具体按[检查点设计](checkpoint-design.md)准备局部对照。

前段已异常就向其输入与计算回查；前段正常、后段异常时，检查两点之间的计算、地址和数据依赖。比较需对应同一批逻辑数据及适用判据；缺少可信局部依据时可先保留数值或不变量观察，但不能宣称找到了首次计算错误。

同一依赖链上已有可比、稳定的正常/异常端点，且有依据支持局部单调假设时，可用[语义二分](semantic-bisection.md)缩小当前判据的边界；误差累积、抵消或出现 `PASS → FAIL → PASS` 时，按[逐层分析](progressive-error-analysis.md)调查产生与传播。插桩改变原现象时，按 [DumpTensor 方法](dumptensor.md#数据就绪与插桩影响)解释本轮结果，保留未插桩时的原始证据。

## 范围收敛后的下一步

把已有依据串成“哪个输出或位置异常 → 对应哪段代码或数据关系 → 当前候选及下一项检查”。只报告已核对的范围，内部阶段或归属未知时注明，不强行缩成最小区域或某行代码。

新观察或源码事实支持具体候选时，进入[假设与实验](hypothesis-experiment.md)验证；没有候选或仍无法区分时，按当前缺口补最有用的观察，不重复相同缩区，也不重新开启全算子范围的猜测。定位到某个 tile 或看到数值吻合，都不自动等于确认根因。
