## 建立算子模型

根据已有现场记录，明确数学公式、reference 定义、输入输出角色、shape/axis、dtype 行为、有效区和验收要求。区分数学定义、项目 golden、局部算术模型和 NPU 实机结果，不用 API 名、文件名或最终错误位置代替模型。

若公式存在等价变形，记录项目实际采用的形式；reference 使用更高精度或不同运算顺序时，按已确认的中间 dtype、Cast、累加方式与舍入点建立局部参考，具体见[局部算术模型](numerical-modeling.md#局部算术模型)。

## 从输出类型建立局部比较链

选择 checkpoint 前，先明确当前输出的语义、比较模型和有效区。多输出或复杂计算链可用简短记录区分 oracle、特殊值规则与实际路径；不同输出按各自判据比较。

| 输出类别 | 按当前问题核对 | 合适的局部 oracle 候选 | 常见误判 |
|---|---|---|---|
| 搬运、置换、索引 | 输出坐标到输入坐标的映射、padding 与 alias | 唯一坐标编码、逐元素值或项目要求的位模式 | 只比较扁平数组，漏掉值正确但位置错误 |
| 整数算术 | 精确公式、溢出、符号与非法输入语义 | 独立整数实现或可手算边界 | 用浮点容差掩盖 off-by-one 或索引跳变 |
| 浮点算术 | 中间 dtype、累加方式、舍入点、结合序、特殊值和输出 Cast | 项目 reference、按已确认舍入点建立的独立局部算术模型 | 用高精度整式要求低精度中间点逐位相同 |
| 量化/反量化 | 量化轴、scale、zero-point、舍入、饱和和输出类型 | 独立编码/解码链与边界样本 | 只看最终 dtype，遗漏 scale 或饱和语义 |
| 随机语义输出 | 分布、范围、seed、状态推进及项目要求的序列性质 | 对应的统计检验与状态/序列对照；按项目要求逐点复现 | 只验边际分布，遗漏状态推进或序列要求 |

随机输出的分布与序列要求按[随机输出验证](baseline.md#随机输出边际分布与序列义务分开验证)分别检查。非随机算子在固定输入下意外漂移，先按[复现性方法](reproducibility.md)核对随机源、同步、初始化和缓冲复用；项目允许的非确定性归约仍按原数值判据比较，不能仅因结果变化就改用分布验收。

缺少项目 oracle 时，可选择独立实现、基本算子组合或不变量对照，用可手算小例等方式确认其可靠性。说明它能判断什么；复用 Kernel 的索引函数或常量表会共享错误，不能据此声称独立验证。

局部对照通过只说明本次样本满足该点采用的判据，不能证明后续搬运、同步或消费者正确。自建模型与 actual 一致也只提高候选优先级，不能用 actual 反推模型后再称其为独立证据。最终验收仍沿用项目比较模型，不用局部模型替换原验收标准。

## 确认需求与相关路径

从题面或项目规格确认本次涉及的输出、输入范围和验收要求；来源冲突时保留疑点，不自行放宽标准。现有测试是验证入口，不能替代明确的项目要求。

沿 Host 与 Kernel 的实际分派确认当前路径。修改涉及共享函数或路由时，查受影响的调用方，再选择相关边界和代表性用例；复杂多路径任务可用简短表格辅助整理，不要求每个任务建立覆盖矩阵。

## 画出实际计算链

围绕待分析输出，从 Host/tiling 分派和 Kernel 源码串起相关路径。按当前疑点补充：

- 搬入、layout/reshape/broadcast 和有效区变化；
- Cast、Reduce、Exp/Log、Div/Reciprocal、Matmul 等计算节点；
- queue/buffer 生命周期、同步、多核分片、尾块和写回；
- 用于解释该段计算的 dtype、shape、layout、源码位置和输出语义。

在链上标记低精度累加、相近数相减、极值、特殊值、归约顺序、对齐/padding、跨核可见性等敏感点。敏感点用于设计观察和假设，不自动成为根因。

## 把计算链对应到执行与存储

不清楚存储层次、执行单元、数据通路或 SIMD/SIMT/Reg 编程形态时，直接调用 CANNBOT `npu-arch` 技能确认目标架构的背景与能力，再回到当前源码建立实际链。本页不另维护产品映射、容量表或典型硬件拓扑。

对当前疑点涉及的数据边，核对并记录：

- 生产者、消费者及所在的流水、核或线程范围；
- 源/目的存储位置、地址、layout、有效范围、dtype 和实际调用；
- 数据写入完成、消费者读取、下一轮允许复用的时点，以及相关同步或所有权。

`CopyIn` / `CopyOut` 是代码阶段名，不能代替实际通路；变量声明或位置标签也不能单独证明物理独立与数据就绪。按真实地址、调用与依赖选择观察点，具体 DataCopy、LoadData、矩阵计算及搬出语义调用 CANNBOT `ascendc-docs-search` 技能核对。

### 先识别编程形态

依据实际采用的构建分支和 Kernel 路径选择观察面：Memory 形态看搬运前后的张量，Reg 形态拆开 Load、寄存器计算和 Store，SIMT 形态追踪线程索引与指针；混合形态还要标记外层 Kernel 与 VF 边界。

调用 CANNBOT `npu-arch` 技能查询模型概念、支持架构和条件编译含义；源码中出现某类 API 或存在某个分支，不证明本次执行采用了该形态。

## SIMT 的线程与共享范围

调用 CANNBOT `npu-arch` 技能查阅 SIMT 指引，确认线程层级、调度和共享存储范围。定位时从实际启动配置和索引表达式反推每个观察值属于哪个 block/thread、输入输出区域及循环轮次，不用典型线程数代替本次配置。

对共享数据检查写者、读者、生命周期与同步参与集合；分支或提前返回是否漏掉必要参与者，继续按[同步与可见性](../patterns/mechanisms/pipeline-sync-visibility.md)检查。已知线程分组或源码先后顺序不能单独证明相关依赖已完成，具体屏障、栅栏与 VF 调用约束调用 CANNBOT `ascendc-docs-search` 技能核对。

## 完整性检查

核对计算链是否对应实际构建和执行路径。宏分支、tiling 分支或编程模型尚未确认时，标出候选路径和待确认点，不把源码中存在的分支当作本次执行事实。

已有信息足以选择候选或观察点时，就进入下一步，模型随新证据补充：

- 已有具体候选原因：按[假设与实验](hypothesis-experiment.md)检验它的预测。
- 尚不清楚哪一段异常：按[观察点设计](checkpoint-design.md)选择能区分相关环节的局部观察。
- 实际分支未确认且影响当前判断：先补构建产物或运行证据；证据暂缺时，继续不依赖该分支的分析。

验证结论限于实际检查的输入和路径，其余范围按与当前问题的关系说明。
