# 假设与因果实验

本页帮助把源码疑点变成可验证的解释，再根据结果继续定位。已有证据可直接复用；初筛范围与退出条件沿用 [SKILL 阶段 3](../../SKILL.md#阶段-3定位问题与验证根因)。

## 低成本验证

从本轮要解释的错值、位置或触发条件出发，用一句话说明：**哪处实现，在什么条件下，怎样造成这个差异**。候选应有源码或观察依据；暂时说不清时，先按[检查点设计](checkpoint-design.md)补观察，不随机改代码。

按当前缺口选一个检查：

| 当前疑点 | 具体怎么做 |
| --- | --- |
| 索引、偏移或搬运范围不对 | 从失败逻辑坐标算出应访问的位置，与代码实际计算的位置、对应输入值核对 |
| 公式、参数或初始值不对 | 用已有真实输入计算该写法预测的错值或差值，与 actual、golden 对照 |
| 不确定偏差在哪段产生 | 在可疑段前后选少量可比观察点，核对对应数据；需要观察 Kernel 内部 Tensor 值时，可在对应位置调用 [DumpTensor](dumptensor.md) 输出 |
| 舍入或算术路径有多种解释 | 按已确认的 dtype 和运算语义建立局部模型，比较候选预测；见[局部算术模型](numerical-modeling.md#局部算术模型) |
| 已有具体修改能检验机制 | 作局部、可撤销改动，沿原入口回放失败，检查预测涉及的值或位置是否改变 |

优先选能改变下一步判断、准备和执行成本较低的检查，不要求把上表全部做一遍。多个候选都能解释现象时，优先找它们预测不同的输入或观察点；共同前提尚未确认时，检查它也有价值。例如两个计算候选都假定输入正确，发现入口数据已错就应先查上游。只有一个有依据的候选，也可以验证，不必另凑对手。

## 实验设计

需要运行对照或修改代码时：

1. **写清预期变化**：哪个值、错误位置或数据关系应如何变化；没有变化时，要满足哪些前提才能排除候选。只看整例 PASS/FAIL 不够时，补充目标切片的比较。
2. **保留原比较口径**：沿用实际输入、golden 和验收标准。诊断需要改变输入时，单独记录它与原失败的关系；中间点按[局部判据](checkpoint-design.md#准备局部对照)比较。
3. **控制主要改动**：优先只改变待验证因素，检查是否连带改变 dtype、分派、tile、核数或布局。无法分离时按组合解释，不假定改一个参数就只影响一个机制。
4. **执行并核对**：确认改动生效、实际运行采用新产物、输出属于本轮，再比较预测与实际差异。采用存疑时按[复现性方法](reproducibility.md#核对环境与实际产物)检查；源码正则匹配不能替代运行与采用证据。

## 一个完整例子

以逐元素 `y[i] = x[i] + beta[i]` 为例，以下小整数可精确表示为 float32：

```text
x      = [ 1,  2,  3,  4]
beta   = [10, 20, 30, 40]
golden = [11, 22, 33, 44]
actual = [11, 22, 13, 24]
```

发现相关代码使用 `beta[i % 2]`，怀疑后两个元素重复使用了前两个 beta：

1. **先算预测**：若其他项相同，预测偏差为 `beta[i % 2] - beta[i] = [0,0,-20,-20]`，与 `actual - golden` 核对。吻合后再确认本次确实执行了该索引，且 beta 输入与记录一致。
2. **针对性回放**：确认语义要求 `beta[i]` 后，只修正该索引并运行原失败。预期后两个元素恢复，前两个不变；仍用原比较器判定。
3. **按结果继续**：变化符合预测时，结合实际路径与源码解释确认该问题；偏差未变时，先查改动采用和实际索引，必要时只观察 beta 读取位置。另一区域仍失败时，保留本处结果，再查剩余异常。

这个例子演示“源码依据 → 错值预测 → 针对性验证”。一般浮点计算还需考虑舍入和局部判据，不能把示例的精确差值规则套到所有算子。

## 解释结果

先看本次观察能否用于比较，再判断它对假设意味着什么：

| 实际结果 | 判断与下一步 |
| --- | --- |
| 构建失败、改动未采用、输出陈旧或数据不可比 | 本轮不能支持或排除候选；补齐具体缺口，或改用不依赖它的检查 |
| 目标差异按预测变化 | 核对实际路径与源码解释；证据足够就确认根因，仍有合理竞争解释则继续区分 |
| 有效观察与候选的必要预测矛盾 | 确认触发条件和观察范围覆盖该预测后，排除或修正候选 |
| 多个候选都预测了当前结果 | 保留能确认的共同范围，去预测不同的位置继续观察，不单独认定其中一个 |
| 观察相互冲突或不足以判断 | 指出缺的是哪项数据、条件或对照，补最有用的一项，不重复相同尝试 |

局部恢复但整体仍失败，不自动反驳本处解释；整体通过也不自动证明原因唯一。新反证出现时更新旧判断，保留原始失败与本轮结果。

用简短文字记录结果即可。沿用标签时，`NO_DISCRIMINATION` 表示尚未区分候选，`INCONCLUSIVE` 表示因果判断证据不足。标签用于概括本轮观察，不能替代支持或排除候选的具体依据。

## 按需处理复杂情况

- **多项变化联动**：升精度、改 shape/tile 或单核运行，可能同时改变输入表示、计算路径、分片与调度。核对实际变化，按缺口增加局部观察或对照；多处修改一起通过只证明组合效果，不必穷举所有修改组合。
- **并行或偶发错误**：核对谁写、谁读、何时等待以及缓冲复用和地址所有权。加全流水屏障后恢复，仍需区分这些关系，不能锁定某条同步。按[重复性方法](reproducibility.md#判断稳定性)比较同条件下的失败率、位置和误差，说明样本数；未修改版与干预版的交错对照按需执行。
- **观察本身改变问题**：按 [DumpTensor 的插桩影响](dumptensor.md#数据就绪与插桩影响)保留本轮有效比较，说明对未插桩版本的限制。局部模型吻合也不单独证明设备指令行为，硬件语义缺口按[最小 NPU 数值探针](numerical-modeling.md#最小-npu-数值探针)处理。

## 剩余或新增错误怎么处理

围绕**剩余或新增错误对应的同一输出、区域或性质**比较，已有可比的原始结果可复用：

| 未修改版本 | 修改后 | 下一步 |
| --- | --- | --- |
| 该区域通过，即使别处仍失败 | 该区域失败 | 优先查补丁引入的回归 |
| 该区域已失败 | 该区域仍失败 | 比较错值和触发条件，判断原机制是否仍能解释；不同机制需要不同处置时再分别定位 |
| 缺少可比观察 | 出现异常 | 先保留归因未定，补该区域的对照，不自动归咎于补丁 |

位置不重叠不足以认定两个独立问题。保留总体失败和未完成回归，不靠拆分线索提前关闭任务。

## 确认根因与收口

说明**哪处实现、什么触发条件、怎样产生原始异常**，将实际执行路径、源码推导、预测与观察连起来，并核对已有正常对照和反证。证据充分时直接收口；只支持某个区间或时序相关时，按该层级报告。无法运行时可继续源码或已有数据分析，但保留运行验证缺口。

同类检查不再提供新信息时，初筛按阶段 3 转入系统定位，局部验证则补当前范围内能区分原因的观察；后续候选应有新观察或源码事实支持。有执行时限时，按实际准备、构建、运行及恢复成本安排下一步，给必要回归和交付留出时间；到时仍未闭合，就报告最后验证过的状态与未决项。

清理本次仅用于取证的临时改动；改过执行源码时干净重建并按原入口回放，结果如实保留。要保留为正式修复的修改需符合项目要求并完成相关验证，不能仅凭临时绕过后通过。按用户目标进入[主流程](../../SKILL.md#六阶段调试流程)的修复、回归或报告阶段。
