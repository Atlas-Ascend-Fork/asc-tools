# FP16 升精度：在首次信息损失前改变位置

资料范围：CANN 9.0.0；产品 Ascend910B1；NPU Arch 2201；调用或执行路径 kernel-direct。下述结果仅覆盖列出的输入与执行方式。

这是一个用固定输入说明数值机制的小实验。当最终输出已经是 FP32、但小增量仍消失，或仅在大基数附近出现阶梯状残差时，先画出每个操作数、算术结果和输出的 dtype。这里要验证的是提升发生在首次舍入或信息损失之前，而不是笼统地把最终输出改宽。

probe 比较两条加法链：`FP16 Add → Cast FP32`，以及两个 FP16 操作数先 Cast FP32 再 Add。对 `1024 + 0.0625`，前者输出 binary32 `0x44800000`（1024），后者为 `0x44800200`（1024.0625）；`-1024 + -0.0625` 也发生对应分叉。`1024+1` 和 `-1024+1` 两个精确 control 在两条链中一致。该探针的 256 lane 位模式均无失配、触发组不同、control 相同且无 GM 哨兵残留。

这只观察了加法与 Cast 的上述固定组合。它没有运行减法、相消链、其它算术 callable、其它版本、SoC、长度、tiling、融合或 API 重载。

## 区分实验

为当前失败链添加三个 checkpoint：各操作数进入算术前、第一次算术后、最终输出前。保持同一输入与实际调用，只改变一个位置。

| 触发/对照 | 早期窄化链预测 | 算术前升至宽 dtype 的预测 | 用途 |
| --- | --- | --- | --- |
| `1024 + 0.0625` | 1024 | 1024.0625 | 检查小增量是否在 Add 边界已丢失 |
| `1024 + 1` | 1025 | 1025 | 精确 control |
| 业务基数两侧的正负小增量 | 由当前 dtype/位模式计算 | 由当前 dtype/位模式计算 | 排除只适合单个常量的结论 |

若宽化只发生在第一次 FP16 算术之后，触发输出仍像早期舍入链，说明信息已经丢失；若两个操作数在算术前提升后原先发生分叉的算术后 checkpoint 按预测改变，而 control 保持相同，才支持过早信息损失候选。实际代码中的隐式 Cast、融合、输入量化或不同 API 路径都可能另有舍入点，必须一并记录。

若需要研究 `(1024+0.0625)-1024` 一类相消链，应针对当前任务建立局部算术模型，并按需用独立 NPU 探针核对；上面的 NPU 观察不包含减法，不能用它替代该结论。

## 局部干预与修复代价

只提升首次易丢失的操作数和算术边，保持最终 Cast、有效集合、tile 和其他算术不动。预测、否证条件和预期位模式都应在改动前写下。若原先发生分叉的算术后 checkpoint 未按预测改变，检查构建产物、真实 overload 和上游量化；不要继续把宽 dtype 向下游扩散。

更宽的中间表示会增加局部存储、带宽、可用重载限制和可能的调度差异，也可能改变特殊值及任务要求的逐步舍入语义。因此修复后除了原触发/control，还要覆盖实际完整/tail、正负增量、边界邻点和当前合同涉及的特殊值。

## 回归与结论边界

若当前 oracle 规定 FP16 Add 后才转为 FP32，`1024` 就是该合同下的正确结果，不能因为 `1024.0625` 更接近实数和而擅改计算链。验收记录应包含输入位模式、每个 checkpoint 的 dtype/位模式、实际调用、产物身份与最终输出。只有“首次舍入或信息损失前提升有效、已丢失后提升无效”的对照同时成立，才把根因收敛到该边。
