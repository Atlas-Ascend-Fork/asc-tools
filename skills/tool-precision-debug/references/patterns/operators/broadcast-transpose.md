# 广播与转置算子族

## 数学与 reference

Broadcast 改变逻辑索引复用，Transpose 改变坐标到物理地址映射；reference 必须按逻辑 shape 计算。

Broadcast 先写出输入坐标到输出坐标的映射以及广播轴，Transpose 写出轴排列和逆排列；随后才将逻辑坐标映射到 layout/stride。右对齐、维度 1 和非连续输入是逻辑合同，block 数、padding 和搬运 stride 是物理实现，不能互相替代。

## I/O 与实际链路

- 冻结输入/输出 shape、dtype、layout、有效区、padding 和 alias。
- 从 host tiling、GM 搬入、局部计算、同步到 GM 搬出逐节点记录实际计算链，不以 API 名替代。
- tiling 分支、多核分区、尾块与特殊值必须进入风险清单。

## 手写轴置换的检索与建模

`tensor_3d_permute`、三维轴置换、轴排列/逆排列、展平索引和手写转置都先路由到本算子说明。先写出输入坐标、输出坐标、轴排列及其逆映射，再分别展平为元素索引；索引单位和物理地址单位不能混用。

算子名称含 `transpose` 不等于实际调用 `AscendC::Transpose`。只有从真实 Kernel 调用链确认该 API 后，才查询对应的版本 API 文档；手写 `GetValue`/`SetValue` 或其他索引实现仍按实际读写链和坐标映射建模。本页不据算子名预判具体题目的根因或修复。

## 敏感 checkpoint

按疑点从输入解码、布局/搬运、消费者前后和最终有效输出中选择少量相关观察，说明观察面、元素映射与参考依据。缺局部 oracle 时先保留原值或检查适用的不变量，不据此排除整段计算。具体见[观察点设计](../../diagnosis/checkpoint-design.md)；仅在已有可比误差且需要解释传播、放大或抵消时，使用[逐层分析](../../diagnosis/progressive-error-analysis.md)。

使用每个轴系数不同的可逆坐标编码，并配对测试无广播、单轴广播、多轴广播、维度 1、非连续输入和尾块。若值来自正确输入坐标但落在错误物理位置，转查 layout/stride；若源坐标本身错误，保留在本算子说明。特定广播指令的输入块数或对齐限制属于版本 API 事实。

### Broadcast shape/stride 双账本

- **何时查**：输出 shape 正确但某一轴重复错、同一源值没有在预期坐标复用，或错误周期随 stride 改变时查询。
- **查什么**：先按当前算子合同对齐 rank，并为每个输出坐标写出逻辑源坐标；广播轴的逻辑源坐标固定到该轴唯一位置，非广播轴保留输出坐标。再用真实物理 stride 独立计算源元素 offset。把“逻辑上等效为零步长”与 Tensor 实际保存的 stride 分开，不能篡改物理元数据来模拟广播。
- **怎么证伪**：选择两对输出坐标：一对按合同应共享源坐标，一对不应共享；若两对的源坐标和实际读地址都与 oracle 一致，而首次错误在消费者之后，就降低广播映射候选。
- **反串线**：源坐标错误归广播；源坐标正确但地址错归 layout/stride；地址和值均正确但消费者错则转下游。具体 API 的 rank、axis、临时空间和对齐限制只查询对应版本页，未覆盖组合保持 `UNKNOWN`。

### Permutation 逆映射与交换图

- **何时查**：转置后值集合相同但位置错、转置与广播组合才失败，或连续物化能恢复时查询。
- **查什么**：同时记录 permutation `p` 和逆排列 `p^-1`，对探针坐标分别计算 `out_coord -> in_coord -> input_offset`。若任务合同允许广播与转置交换，另画两条逻辑等价路径，并在转置后同步重排广播轴；没有该等价合同就不做交换假设。
- **怎么证伪**：在纯逻辑 reference 上验证 `p^-1(p(x)) = x`，再比较原路径与“先手工广播后转置”或 “先转置后按重排轴广播”的有效区。只有两路使用相互独立的置换实现，且进入消费者前都分别匹配独立 oracle，而消费者后才同向分叉时，才降低 permutation 候选；两路共享同一 Transpose 实现时只能记 `NO_DISCRIMINATION`。
- **反串线**：逆变换通过只证明被采样坐标可逆，可能同时保留相互抵消的两次错误；还要检查单程坐标指纹。连续 staging 会改变容量、tiling 和同步，只是定位实验，不自动证明正式修复。

## 手工物化与 Padding Control

为隔离广播逻辑，按 reference 坐标映射在 host 侧把源值手工展开为稠密逻辑 Tensor，并保持有效区值、dtype 和下游计算不变。手工展开通过而原广播路径失败时，广播的物理实现或布局是候选；两者都失败时，继续检查轴置换或下游消费者，不能仅凭算子名归因。

为隔离物理块，在每个块只填充有效 lane；只有物理缓冲区已经分配这些 padding lane、且当前合同允许诊断代码写入和观测时，才分别使用两组可区分哨兵。有效输出随哨兵变化说明无效区泄漏到搬运或计算；输出不变则降低 padding 候选。padding 是否分配或可写未知时不触碰它，改用有效区/连续物化对照并保持 UNKNOWN。实际块形状和特定广播 API 约束只从 tiling 与对应版本的官方文档读取。

Transpose 后再做一组 view 与连续 staging Tensor 的对照：两者逻辑值和轴映射相同，仅显式物化连续存储。staging 通过而 view 失败时提高连续性、stride 或布局候选；两者同样失败时优先复核排列公式和消费者。手工物化会改变容量、tiling 或执行路径，只用于定位，不能直接当成正式修复证据。

## 小通道转置与转换链

小通道场景可把“装载槽位是否完整”和“输出哪些通道有效”分开检查。历史 C 不超过 16 的 TransDataTo5HD 组合写法，会为未用输入行提供合法的已有行，并在转置后只提取逻辑有效通道；采用前应核对当前重载和真实布局，不能让补齐值进入有效输出。偏移表按输入与输出坐标推导，先用坐标编码核对一整个周期。

FP32→half→转置→Gather(half)→uint8 的组合还可能在转置之前丢失量化边界信息。整数输出相差 1 时，在每次转换前后比较边界两侧输入；按原算法规定的取整方式和时机修复，不能直接加一个 round。布局接口、临时空间、重叠方式与产品支持调用 CANNBOT `ascendc-docs-search` 技能核对，有效数与掩码状态见[筛选后的有效区](../mechanisms/data-movement-alignment.md#筛选后的有效区与状态)。
