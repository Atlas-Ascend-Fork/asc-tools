# Convolution 算子族

## 数学与 reference

先冻结卷积维数、输入/权重/输出逻辑 shape、stride、dilation、group、padding、bias、dtype 和 layout。reference 必须与当前任务对 padding 值、输出尺寸和累加顺序的合同一致；不要从某个框架默认值推断。

## 实际计算链

按当前疑点展开 Host shape/tiling、输入与权重搬入、layout 转换、im2col 或等价展开、L0A/L0B 准备、Cube/MMAD 累加、后处理及搬出中的相关环节。为所选数据边记录有效区与参考依据，高阶 API 名称不能替代实际链路。

## 敏感 checkpoint

从下列位置按疑点选点，参考与采集前提见[观察点设计](../../diagnosis/checkpoint-design.md)。缺局部 oracle 时可先保留数值或检查适用的不变量，无法判定的部分保留未知，不要求全链采集。

1. padding 后的逻辑输入与边界窗口；
2. im2col/LoadData 后首个内部矩阵；
3. 权重布局转换后的首块和通道尾块；
4. 主累加器在首个 K 块、尾 K 块和合并后；
5. 后处理前后与最终有效输出区。

## 区分实验

构造无 padding 与有 padding、单通道与通道尾块、单 K 块与多 K 块、单位 stride 与边界 stride 的配对输入。若误差只在空间边界，先比较 padding/im2col；若按通道块周期重复，检查权重布局与尾块；若随 K 增长，检查累加 dtype 和合并顺序；搬入已错时不要先修改 MMAD。

## 空间窗口与通道坐标 oracle

对首错输出坐标 `(n, co, ho, wo)`，先由当前算子合同展开它实际依赖的输入窗口和权重坐标；stride、dilation、group 与 padding 都必须来自本次任务，而不是框架默认值。为输入有效区使用 `encode(n, ci, hi, wi)`，为权重使用不同量级的 `encode(co, ci, kh, kw)`，使 im2col 错位、权重错位和输出通道映射得到不同预测。编码必须在载体 dtype/范围内精确可表示，并在当前有效坐标域内无碰撞。还须证明卷积累加的最坏范围不会溢出，并在实验前用预测表确认各竞争映射会产生不同输出。只比较真实分配且允许观察的有效区；padding poison 还必须是接口语义允许的值。padding 未分配、不可写或 poison 不合法时不放哨兵，改用无 padding/有 padding 的成对 shape 与逻辑边界窗口 oracle。

若只有输出图像四周错误而中心匹配，依次比较逻辑 padding 窗口 oracle（或真实可观察的对应 checkpoint）、首个边界窗口的 im2col 展开和相应 CO1 坐标。关闭 padding 后通过只支持“分叉依赖空间边界”，不能单独区分 padding 值、窗口映射或边界有效区。若误差按输出通道块周期重复，则同时冻结权重块、输出通道映射和通道尾块；数值集合相同但通道坐标错位优先保留布局候选，不先调整累加精度。

### 从输出坐标反解窗口

- **何时查**：首错集中在四周、只在非单位 stride/dilation 出现，或相邻输出点读取了看似正确但错位的输入值时，先查窗口坐标，不先查累加精度。
- **查什么**：对每个探针输出 `(n, co, ho, wo)` 写出当前任务的 kernel 方向、group 映射和输入坐标等式。在常见的非翻转相关合同下，可用 `hi = ho * stride_h - pad_top + kh * dilation_h`、`wi = wo * stride_w - pad_left + kw * dilation_w` 建账；若任务合同会翻转 kernel、使用不同轴序或非对称 padding，就必须改写等式，不能硬套该示意。账本同时列出窗口内有效坐标与应走 padding 语义的坐标，并把每个贡献绑定到权重坐标。
- **怎么证伪**：用单一输入坐标和单一权重坐标激活，预测它应影响的全部输出坐标；若 padding 后输入与展开矩阵逐项符合该依赖集合，而主计算后才分叉，就降低窗口/padding 候选。
- **反串线**：关闭 padding 后恢复只能说明错误依赖边界，不能区分窗口公式、padding 值和有效区；具体 LoadData 参数、padding 行为与产品支持仍路由当前版本 API，缺证据时标 `UNKNOWN`。

### Group、Dilation 与通道归属的正交实验

- **何时查**：只有 `group > 1`、`dilation > 1`、某组输出通道或某个膨胀采样相位失败时查询。
- **查什么**：从任务合同记录每个输出通道所属 group、该 group 可读取的输入通道集合、核内坐标与膨胀后的实际输入坐标；为不同 group、输入通道和核点配置互不碰撞的指纹。
- **怎么证伪**：固定输出空间坐标，依次只激活同组通道、相邻组通道和一个 dilation 空洞中的坐标。若只有合同内贡献出现、跨组与空洞 control 均为零，且展开结果正确，则降低 group/dilation 映射候选；再增加参与项后才漂移应转向累加或合并。
- **反串线**：按通道块周期错误也可能来自权重 layout、输出通道 tiling 或多核所有权；只有错误值能被 group/窗口坐标预测且首分叉位于展开边，才归到卷积坐标合同。

## K 参与集合与增长实验

卷积共享维由合同决定，通常可由输入通道和核窗口展开为若干贡献。用单块激活、多个完整块激活、尾段单独激活和全零 control 建立参与集合；每组保持输出窗口、权重布局和后处理不变。漏块会让对应唯一贡献消失，低精度累加更常表现为贡献都存在但偏差随参与项增加。这里的 tail 只指合同内逻辑有效 tail，不把物理补齐当贡献。两类现象都可能随共享维增长，只有局部 checkpoint 才能区分。单 K 块通过不能外推多块合并，尾段失败也不能在未验证 padding poison 是否进入计算前宣布是尾 K 参数。

本页用阶段链、窗口 checkpoint、坐标编码、参与集合和预测表组织实验。接口签名、单位和产品支持调用 CANNBOT `ascendc-docs-search` 技能查当前原文；普通方法页或 CPU 行为不升级为强事实。Load3D 要核对 `padList`、`padValue`；对使用 `IsResetLoad3dConfig` 的重载，分别确认 `isSetFMatrix`、`isSetPadding` 是否让本次配置生效，或要求调用前另行设置状态。Mmad 与基础 Fixpipe 分别核对类型组合和 L0C→GM/UB/L1 通路。文档分支与当前头文件不一致时，保留两边来源并做最小实验。

## 修复与回归边界

依据具体代码问题、触发条件和致错机制实施修复，再按影响范围回归相关的空间/通道边界、layout、K 尺寸、group 与后处理组合。首次可见分叉或超差不自动等于根因；局部通过而后段失败时，按[逐层分析](../../diagnosis/progressive-error-analysis.md)区分新增差异与上游偏差传播。卷积、LoadData、MMAD 的精确参数与支持范围查询当前版本 API；本页不代表任何具体 Conv 实现已在当前 NPU 验证。
