# 累加、归约顺序与消减

误差随归约长度、tiling 或核数变化时，优先区分累加 dtype、分组顺序、尾块参与和跨核合并；也要排除只是输出尺度变大。

## 确认比较目标

按[比较与验收](../../diagnosis/baseline.md#数值相等与逐位一致)确认当前输出要求容差、数值相等还是逐位一致。最终位一致不自动要求内部归约树相同；项目明确规定求值顺序时，再核对该要求。

查看当前相关节点的输入与累加 dtype、归约范围、输出 Cast 和 reference。FP32 累加仍失败时，可比较单块与多块 partial、合并顺序和局部 oracle，避免重复尝试升精度。

## 判断归约顺序是否相关

浮点加法不满足结合律，元素集合相同也可能因分组不同而产生位差。根据疑点选择观察：

| 当前疑点 | 有用的观察或对照 |
| --- | --- |
| 局部树、split 或尾块 | 比较相关边界前后的长度和每级配对，检查尾部元素是否参与 |
| 分块或跨核合并 | 区分 chunk 内归约、partial 存储 dtype 和最终合并；局部结果正确不代表完整合并正确 |
| 消减或特殊值传播 | 选择对顺序敏感的输入，追踪首次差异；必要时查[特殊值](special-values.md) |

怀疑 pairwise 顺序，或项目要求复现该顺序时，从实际 reference 查 leaf、split、对齐与取整方式，不能仅凭 `n/2` 或库名推断。具体 CANN 重载的归约层级与支持条件调用 CANNBOT `ascendc-docs-search` 技能查询。

## 框架参考的分层归约与主尾列分派

逐元素输出正常、只有 sum/bias 超差，或者主列修复后只剩尾列失败时，检查参考实现自身的分派。`sum(axis=0)` 不足以描述实际加法次序；相同的归约长度也可能因未归约维宽度、stride、CPU SIMD 分派和线程划分而采用不同路径。

先保留生成 golden 时的框架版本、设备、实际 CPU capability、线程数，以及归约输入的原始 shape/stride/dtype。Agent 本机的 CPU 或编译器检测值不能代替生成参考值的进程。源码可用时，直接沿该版本的分派条件和循环推导，再用少量对抗输入核对；反复拟合随机输出容易把局部规律当成完整算法。

以 [PyTorch 2.9.0 的 SumKernel](https://github.com/pytorch/pytorch/blob/v2.9.0/aten/src/ATen/native/cpu/SumKernel.cpp) 为一个具体例子：对连续 FP32 矩阵沿非连续的 batch 轴求和，`vectorized_outer_sum` 在主列调用 `multi_row_sum`，剩余向量列和标量列调用 `row_sum`。以下只描述这条源码路径，不是所有 `torch.sum` 或 NPU ReduceSum 的规则。

| 路径 | 实际次序中容易漏掉的部分 |
| --- | --- |
| `multi_row_sum` | 四层 FP32 accumulator 从 `+0` 初始化；正长度 `N` 的步长为 `2^max(4, floor(ceil(log2(N))/4))`。低层满块向高层累加并清零，末尾不足一块留在低层，最后按低层到高层合并 |
| `row_sum` | 先将完整的四行组按 `row % 4` 拆成四条交错链，对长度 `floor(N/4)` 的链分别执行上述 cascade；空链保持零初值。各链层级合并完成后，剩余 `N % 4` 行依次追加到第 0 链，最后依次合并第 1、2、3 链 |
| 主列与尾列边界 | 在上述向量外归约路径中，主列宽度是 `4 * V` 的整数倍，`V` 是参考进程实际使用的 FP32 SIMD lanes；参考宽度为 `C` 时，边界为 `floor(C/(4*V))*(4*V)`。不满足该分派条件时，应另查实际路径 |

即使步长为 16，“每 16 行求和，再顺序累加所有 partial”也只实现了一部分层级：跨过 256、4096 等层级时，进位、清零和最终合并可能改变结果；更大归约长度还会改变步长。尾列也不是简单将所有行按模 4 分配到底，余数追加时机需要单独核对。

### 能区分路径的低成本实验

1. 固定同一列的 FP32 输入字节，比较实际 reference、按源码实现的主列/尾列模型与当前设备归约；高精度实数和另列为数学观察。逐步 FP32 舍入不可只在最后模拟一次。
2. 按真实步长 `S` 选择 `S-1/S/S+1`、`S²` 附近和带不完整组的长度；按真实主尾边界选择相邻列。只覆盖当前候选会分叉的边界，无需枚举全部 `B×H`。
3. 将相同数据复制到主列和尾列，保留整张矩阵的 shape/stride，再比较两列结果。另做原矩阵求和后取列与先抽取列再求和的对照；抽列、转置或 `.contiguous()` 可能改变参考分派，后者不能自动充当原节点的局部 oracle。

一个可手算的区分输入是 `A=2^25`，某列沿 batch 为 `[A,1,-A,1,A,1,-A,1]`。在每步 FP32 最近偶数舍入、步长至少 16 的上述模型中，主列结果为 `1`，四路交错尾列结果为 `2`，精确实数和为 `4`。它说明“主尾列不同”和“更接近实数和”是不同观察；这是数值模型，不是特定 NPU 的实测结果。

### 处置边界

当前验收若要求与固定 reference 对齐，修复需覆盖实际触发的层级、主尾列、余数、输出 Cast 和合并阶段。可以并行处理互相独立的输出列；把归约轴重新切成任意 partial 再合并，仍可能改变目标次序。单行 tile、关闭 group 或更高精度累加是可选对照或特定实现方案，不能因一次通过就推广为通用修复，也不能忽略性能和 UB 代价。

需求仅规定 FP32 求和，而固定 oracle 的特殊值规则事实上要求某种结合树时，保留这个可复现的要求差异，交由评测维护者确认；调试期间继续使用原判据，不擅自更换 golden、清洗特殊值或放宽阈值。案例及主列修复后的尾列反例见 [GRU bias 归约](../cases/thnn-fused-gru-bias-reduction.md)，溢出分叉见[特殊值中的归约顺序](special-values.md#有限输入的归约顺序也会改变非有限类别)。

## 二叉树不等于按量级排序

二分规定的是索引配对，不会自动把相近量级放在一起。例如令 `A=2^25`，每次加法按 FP32 最近偶数舍入：

| 输入顺序 | 左折叠 `((x0+x1)+x2)+x3` | 半区折叠 `(x0+x2)+(x1+x3)` | 精确实数和 |
|---|---:|---:|---:|
| `[A,1,-A,1]` | `1` | `2` | `2` |
| `[A,-A,1,1]` | `2` | `0` | `2` |

同一树形在两组输入中分别改善和放大误差。这个模型不代表某个 NPU API 的执行顺序；用于当前定位时，应检查实际配对和中间 dtype 是否能解释观察。

## 选择实验与回归范围

可从正负大数夹小数、强消减、全同号或长度边界中选择能区分候选的输入。保持参与元素集合可比，单独改变累加 dtype、分块或合并顺序；怀疑尾块时增加完整块对照。

修改共享归约函数或路由后，按实际受影响的调用方选择代表性回归。路由边界应有实现或资源条件依据；一个失败长度不足以确定整段输入都要改路由。`volatile` 或融合、展开开关可用于观察编译行为的影响，不能仅凭开关变化断定实际舍入顺序。

对 count 重载，可由 dtype 计算每个 256B repeat 的元素数，核对 full repeats 和 tail；mask/repeat 重载则核对 mask、repeatTime 与 stride，避免混用两种调用方式。

## 小增量吞没与量级扫描

对 `log(1+x)`，比较 `s = round_dtype(1 + x)` 与 `y = log(s)`。若 `s` 已等于 `1`，信息在加法处丢失，扩大下游 dtype 不能恢复；若 `x` 更早已量化，还需区分输入量化与加法吞没。

在正负两侧扫描邻近量级，找出 `1+x` 首次不再舍入为 `1` 的边界。阈值由实际 dtype、模式和位模式确定，不照搬常量。稳定公式或补偿算法的采用，仍以项目语义和目标 API 支持为准。

## 判断结果

顺序或 dtype 的改变能按预测解释误差变化时，才支持相应候选；单个样例改善不能独自确认根因。

若单块正确、partial 合并后才错，可查[Partial 统计合并](../cases/partial-statistics-merge.md)，区分不等长状态、空 partial 和合并公式问题。
