# 精度模式、近似路径与 Fallback

同一数学公式在 dtype、API 模式或实现路径变化后出现窄带误差，不等于已经确认 fallback。先区分输入量化、显式 Cast、API 近似误差、非原生实现路径、特殊值模式和下游放大；这些机制可能叠加但实验上必须逐一操纵。

若下游是整数舍入、量化或阈值分支，小的浮点扰动也可能跨过离散分界。先比较分界前的实际值及其邻域，保持输入位模式与其他路径不变；从最终输出反解出的 ULP 偏移只是候选，不能替代设备中间值或单指令测量。动态量化的敏感输入与参数链见 [动态量化：统计范围、scale 角色与舍入边界](../operators/dynamic-quant.md)；除法重载与精度配置按实际 profile 查询 API，不能跨架构借用。

## 建立实际路径

架构的数据类型能力、编程模型和条件编译含义调用 CANNBOT `npu-arch` 技能查询；具体 API 是否支持该 dtype、模式及误差保证仍按目标版本调用 CANNBOT `ascendc-docs-search` 技能确认，不能仅凭架构具备某种能力就认定当前调用采用了它。

记录精确 CANN、SoC、编程模型、API 重载、输入/中间/输出 dtype、显式模式、编译分支和生成物身份。API 是否支持某 dtype、采用何种算法以及误差保证属于版本强事实，只能从对应版本 API 文档获得；不能从历史案例症状、编译成功或另一个 dtype 的行为反推。

## 放大链分析

在 API 输入、API 输出和第一个敏感消费者处保存值与位模式。把局部误差传播到后续乘除、阈值、指数、归一化和特殊值分类，寻找“微小 ULP 差异何时变成分支、Inf/有限值或容差类别差异”。随机低比例失败应先收窄成可重复数值带，再评估模式。

## 算术替换与近似路径

设备 Div 改成 Host 求倒数后 Muls、标量广播改成另一种算术接口，可能改变舍入位置和调用路径。固定输入、dtype 与后续消费者，先比较替换点的局部输出，再看最终误差。Reciprocal/Rsqrt 的误差略超容差时，调用 CANNBOT `ascendc-docs-search` 技能取得当前算法模式的精度说明，再选择对照；Div、Sqrt 等替代组合也要满足原验收要求。

大输入下 Sqrt 变成 0、Rsqrt 变成 Inf，先查所用重载和算法模式的输入范围。只在合法输入内做模式对照，不用截断合法输入掩盖错误。次正规值变零与整型溢出另查[特殊值机制](special-values.md)；半精度小增量丢失则继续按下方 Cast 阶段图定位。

矩阵乘的 HF32 开关需要连同 Host、框架和 Kernel 实际状态检查，见[矩阵乘的 HF32 排查](../operators/matmul-mmad.md#hf32-与中间精度)。

## dtype 与 tiling 的二维对照

把 dtype 和 tiling/长度作为两个独立轴，而不是只做一次 FP16/FP32 对比。第一组固定实际低精度输入位模式，用逐步量化的 CPU oracle 对照 Kernel；第二组保持 dtype 与输入共同前缀不变，只改变长度或 tiling 边界；第三组冻结 tiling、模式和最终 Cast，只扩大一个中间量。记录每格的 tile 长度、tile 数量、核数、分支、API 重载和生成物身份。

FP16 改为 FP32 会同时改变元素字节数、片上容量预算，并可能改变 tiling、分支、重载或实现路径；结果改善只能先标为混杂证据。若无法保持另一轴不变，应明确写成“未能因果区分”，再用相同 dtype 的长度扫描或相同 tiling 的单中间量实验补证，不能把 dtype A/B 直接写成精度根因。

## FP16 输入、FP32 中间与输出 Cast 的阶段图

当输入/输出都是 FP16，但最终误差像过早降精度、出口窄化或某个 FP32 中间被绕过时查询本节。先按实际执行画图，不把“混合精度”当成单一模式：

```text
GM half → CopyIn/UB half → Cast#in → FP32 stage 1 → ... → FP32 stage n
        → Cast#out → UB half → CopyOut/GM half
```

为 `Cast#in` 前后、每个敏感 FP32 stage、`Cast#out` 前后保存 dtype、API 重载、有效区、数值和位模式。入口 half→float 与出口 float→half 的支持模式须调用 CANNBOT `ascendc-docs-search` 技能核对；“入口无损”不等于后续 FP32 算法与高精度 oracle 位级一致，“出口只差一次舍入”也须由 Cast 前已经一致来证明。

用单变量 Cast 时机实验定位：一次只把一个 Cast 边界跨过一个操作，例如比较“操作 P 前升 FP32”与 “P 后才升 FP32”，或比较“操作 Q 前降 half”与“Q 后再降 half”；输入位模式、shape、tiling、mask、其余 dtype、模式和输出比较规则全部冻结，并为两条逐操作链各算局部 oracle。若移动边界同时改变 API 重载、tiling、UB 容量或生成物分支，结果标为混杂证据，不写成 Cast 时机根因。一次把整条链全部改成 FP32 只能证明组合路径改善。

支持证据是首个分叉随同一个 Cast 边界移动，且两条链分别匹配事前 oracle；只有最终误差下降、或更换 RoundMode 与中间 dtype 同时发生，均不能区分舍入模式和时机。反例是 Cast 前已经出现错位，此时后移/前移出口 Cast 不会修复上游 layout、group offset 或 K-block 参与集合。

需要固定范围内的早/晚提升触发与精确 control 时，按需查看 [FP16 升精度：在首次信息损失前改变位置](../cases/fp16-promotion-boundary.md)；该案例不覆盖本页的其它算术、模式或编程模型。

### 升 FP32 是否保住了下一个消费者需要的信息

不要只因两个输入“同量级”就认定加法无额外舍入。在最近偶数舍入的 FP16 数值模型中，`1 + 1.0009765625` 的精确和为 `2.0009765625`，舍入为 `2`；两个输入本身都可由 FP16 精确表示。“同量级”与“单次运算无损”不是同一条件。相反，扩大中间 dtype 后立即转回原 dtype，也可能得到完全相同的出口值；是否有收益取决于信息在哪个消费者之前被保留。

用 `a=1024`、`b=0.0625` 的有限正常数对照 `(a+b)-a`，逐步按同一最近偶数模型计算：

| 实际路径 | 预测输出 |
|---|---|
| 加法后存 FP16，再减 `a` | `0` |
| FP32 加法后立即转 FP16，再减 `a` | `0` |
| 加法和减法之间保留 FP32，最后才转 FP16 | `0.0625` |

这是可手算的舍入点对照，不是某个 Ascend C 调用的 NPU 验证。当前任务应先冻结输入位模式、每步 dtype、实际 RoundMode 和输出合同，再预测中间 checkpoint。若只是切换模式或重载才改变结果，不能归功于“FP32 更准确”；若输出合同只要求一次 FP16 加法，上表第三条也不能擅自替换该接口语义。

在二进制幂边界两侧，邻近可表示值的间距可不同，加法和减法的舍入边界也不必对称。按输入位模式和目标间距扫描正负及 tie 两侧；固定量级比不能代替逐操作预测。链长与误差增长见 [累加、归约顺序与消减](accumulation-order.md)。

## MX/E8M0 边界

当前 `9.0.0/Ascend910B1/2201/kernel-direct` 固定 Cast 来源的 Atlas A2 表没有给出 MX 或 `fp8_e8m0_t` 组合，因此该 profile 下的 E8M0 编码、scale 轴、Cast 重载、舍入和特殊值语义全部保持 UNKNOWN。固定仓库中面向 950 的 fp8/fp4/MX 文档或样例不能外推到 910B1；其它环境中的 E8M0 公式和实现建议也需要核对当前产品及接口支持。确认之前不得把 MX 路径作为正式修复。

在当前产品确实支持 MX 路径时，再核对 amax 到 scale 编码的算法与舍入位置。数据格式转换和 scale 编码是两件事；ceil/floor 偏移不能由症状直接选定，需比较解码后的 scale、归一化数值与目标格式范围。数据和系数地址的配对见[矩阵装载](../operators/matmul-mmad.md#装载布局与-scale-配对)。

对 e4m3、e5m2、HiF8 和打包双分量类型，原始位模式必须连同具体格式、分量位置解释。先核对实际转换函数的舍入、饱和与特殊值，再比较数据和 scale 两条链；不同格式的相同字节不表示相同数值。

## 区分实验

1. 固定 API 输入位模式，只切换一个已被当前版本证实可用的模式或 dtype 路径。
2. 同时比较 API 局部误差和最终误差；局部改善但最终不变时，继续寻找下游首次放大点。
3. 保持计算路径不变，仅扩大一个中间 dtype，用来区分近似模式和过早降精度。
4. 在敏感带两侧增加相邻样本，确认结论不是单点巧合或特殊值比较假阴性。

## 修复边界

优先选择满足当前 oracle、输入域和误差合同的正式模式；没有合适模式时，只能在触发域和副作用已完整刻画后做局部修复。不要把“统一转 FP32”“固定 clamp”或案例常量当成通用方案。回归必须覆盖原失败带、带外正常值、dtype 组合、特殊值和当前版本支持边界。

加减法示例采用逐步舍入模型；设备上的实际舍入与中间精度仍需按当前 API 和位模式观察确认。
