# 索引、Offset 与地址归属

稳定错位、输出等于相邻位置、Gather/Scatter 局部异常或多维展平后周期性错误，应先把逻辑坐标、元素 offset、字节地址、搬运块参数和核所有权分层。数值正确但落在错误位置属于寻址问题，不属于舍入。

## 地址账本

对每条读写边记录逻辑坐标、规范化后的 index、展平公式、元素 offset、`sizeof(dtype)`、物理基址、字节地址、有效区和所属核。分别代入首元素、跨行点、边界前后、最后元素和一个非法索引；包含负索引语义时，必须先按当前算子合同规范化，再进入无符号地址计算。

## 支持与反证

- 用唯一坐标编码的输入可以反解出固定错位，且预测地址与错误值一致，支持索引候选。
- 搬运后逻辑值和地址都正确、首次计算后才分叉，应降低寻址候选。
- 周期等于行 stride 或 data block 时，需同时核对 [搬运、对齐与有效区](data-movement-alignment.md)。
- 只在核边界重叠或遗漏时，转查 [多核分区、所有权与核间协同](multicore-ownership.md)。

## 区分实验

用 `value = f(n,c,h,w)` 的可逆编码填充输入，选择能够区分相邻轴和相邻核的系数。对同一坐标同时计算 reference offset 和 Kernel offset，单独固定一个 index 或一个核执行。Gather/Scatter 还要区分 index 生成错误、index 规范化错误和最终地址换算错误；一次只替换其中一层。

系数应由实际 shape 选择，使每个轴的取值区间不碰撞，例如先按最内轴基数递推，再构造 `value = n*K_n + c*K_c + h*K_h + w`；不要复制某个案例的固定常量。编码值必须在载体 dtype 中精确可表示，否则改用整数旁路记录或缩小探针域，避免把编码碰撞误判为地址碰撞。

对 ND 布局，先从值解出逻辑坐标，再独立计算连续元素 offset。对 blocked 布局，仍用打包前的逻辑坐标编码值，并用该次 tiling/layout 给出的实际块形状另算外层块坐标和块内坐标；块形状未知时保持 UNKNOWN，不预设固定通道块。样本应成对跨越行边界和块边界，并比较不同块中的同一块内坐标。值能解出正确逻辑坐标但地址错误时优先查物理映射；值本身解出错误轴时优先查轴排列或索引公式。

### 错值反解与 delta 指纹

- **何时查**：错误输出稳定地等于另一个合法位置、每行错位量固定，或错误呈轴周期而数值本身仍像输入指纹时查询。
- **查什么**：先从 actual 值反解其真实来源坐标 `q`，再与目标坐标 `p` 同时计算 `delta_coord = q - p`、逻辑元素 offset 差和字节地址差；对当前实际存在的行、块、核等边界分别取成对样本，不存在的轴记为 N/A，不能只看一个首错点。
- **怎么证伪**：若反解值没有唯一来源，先换无碰撞编码；若来源坐标正确且读写地址也与 reference 一致，或 delta 随数值内容而非 shape/stride 改变，就降低寻址候选并转计算链。
- **反串线**：固定元素 delta 可能来自轴置换，固定字节 delta 可能来自基址/单位；delta 与 owner、核数或分区边界联动时才提高所有权候选。周期形态本身不能裁决，API offset 单位仍以当前版本页为准。

### 半开区间所有权证明

- **何时查**：单核正常、多核出现重叠/空洞，尾核异常，或 Gather/Scatter 多次写同一目标时查询。
- **查什么**：把每个 producer 的逻辑输出集合和物理写集合都表示成半开区间或显式索引集；记录 `owner`、`begin`、`end`、有效数量、base offset 和允许的冲突/合并规则。验证所有合法输出的覆盖次数，不用“每核平均长度”替代真实尾区间。
- **怎么证伪**：强制单核、两核并成相邻区间、交换核编号，并用每核独立指纹；若集合并集恰好覆盖有效区、互斥合同下交集为空、交换 owner 后错误不随边界移动，就降低所有权候选。
- **反串线**：逻辑区间正确但物理地址重叠属于地址换算；物理区间正确但结果偶发变化转同步/生命周期；合同允许重复 index 时不能把交集直接判成踩踏，应转受控合并或原子语义说明。通用的核参与集合、空洞和尾核分区证明继续路由 [多核分区、所有权与核间协同](multicore-ownership.md)，本节只保留 index/地址到 owner 的桥接。

## Production 模式：索引散写与原子所有权

生产实现中可观察到一种候选模式：运行时 index 先做合同范围过滤，再由多个核或多次更新写向同一目标位置；冲突地址通过受控的原子区间合并。诊断时只采用三项审计动作：在无符号地址换算前验证负值/上界，证明相同 index 是否允许碰撞，以及记录原子模式开启、每次散写和恢复普通写的完整生命周期。具体同步方向、原子 API 和产品支持仍查询官方 API 文档。

区分实验应同时包含非法 index、两个更新命中同一地址、互不冲突的 control 和多核重复运行。若普通写只在碰撞时丢更新，支持所有权/合并候选；若单次单核也写到相邻行，先修正三段 offset 公式。浮点原子顺序可能改变舍入分布，但“每次不同”仍不能越过地址、初始化和可见性证据直接归因于顺序。

## 修复与回归

修正最早错误的坐标或单位换算，不用扩大 buffer 掩盖越界。回归覆盖首尾位置、跨行、跨块、负索引或非法索引合同、不同 dtype 字节宽度和多核边界。API 参数单位和合法范围须在官方 API 文档中核对当前 CANN 的相关差异。

SIMT 的线程层级与共享范围直接调用 CANNBOT `npu-arch` 技能查询；将线程索引映射到本次数据的步骤见[建模中的线程范围](../../diagnosis/operator-modeling.md#simt-的线程与共享范围)，具体 API 调用 CANNBOT `ascendc-docs-search` 技能查询。
