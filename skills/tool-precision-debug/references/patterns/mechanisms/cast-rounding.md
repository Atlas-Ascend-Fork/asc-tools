# Cast、舍入与中间精度

阶梯状误差、半 ULP 差异或只在 dtype 边界失败，可以提高 Cast 候选优先级，但不能直接确认 RoundMode。先保存 Cast 前后的值和位模式，确认首次信息损失是否确实发生在该边。

## 区分实验

1. 固定 Cast 输入位模式，只切换目标版本和精确 dtype 组合明确支持的舍入模式。
2. 样本同时包含正负非整数、tie 两侧、范围边界、正负零和当前契约支持的特殊值。
3. 对每种模式事先计算预测位模式，并确认构建产物采用了修改后的调用。
4. 增加一个完整 repeat 与一个 tail，防止把 mask 或有效长度错误误判为舍入差异。

## 整数进入 FP16 的可表示性探针

不要写成“所有大于 2048 的整数都不能由 FP16 精确表示”。FP16 的有效二进制精度为 11 位：绝对值不超过 2048 的整数都可精确表示；超过后表示间距随指数增大，因此仍有部分整数可表示。例如 2048、2050 和 4096 可精确表示，而 2049、4097 不可精确表示。负值按相同间距规律检查，不用单个正边界外推全部输入域。

用实际业务索引的最小值、最大值和边界邻点做 `integer -> FP16 -> wider/integer oracle` 往返探针，同时保存输入整数、FP16 位模式、回读值和首次碰撞的两个整数。若合同要求逐个整数精确，地址、计数或索引运算应保留整数表示，不能靠容差掩盖碰撞。

`integer -> FP32 -> FP16` 仍受最终 FP16 间距限制，不能绕过窄化；而较大整数在 FP32 中也可能先丢失低位，所以“先转 FP32”不是通用修复。具体 Cast 重载、舍入模式和 dtype 组合是否受当前产品支持必须查询对应版本 API 页；缺少权威证据时保持 UNKNOWN。

## int32 转 FP32：同为四字节也可能丢失整数低位

FP32 有 24 位有效二进制精度：绝对值不超过 `2^24` 的整数都可精确表示，超过后只有部分整数可表示。在最近偶数舍入的数值模型中，`16777217 → 16777216`，但 `16777218` 仍可精确表示；负数按相同间距检查。同为四字节、转换后范围没有溢出，或模式名称含 `NONE`，都不能证明信息无损。

当索引、计数或离散标签在转换后碰撞时，给实际业务范围加入相邻整数、`2^24` 两侧和正负对照，记录整数原值、浮点位模式及回读值。只在转换之后增大 dtype 无法恢复低位；若当前任务要求逐个整数精确，保留整数链作为对照，并核对实际调用支持的模式。这里的数值模型不替代目标 API 的运行结果。

需要一条已限定 profile 的输入、位模式和触发/control 例子时，按需查看 [整数进入浮点链：相邻整数碰撞](../cases/integer-float-collision.md)；它不外推当前任务的 Cast 重载或业务范围。

## 宽化 Cast：数值误差还是存储覆盖

若 FP16/BF16→FP32 后反而出现整段错值，或只有复用同一缓冲时失败，同时检查数值转换与目的区覆盖。`ReinterpretCast` 或另取一个不同 dtype 的 Tensor 视图不等于新分配；对连续有效的 `n` 个元素，源、目的所需字节数分别由 `n * sizeof(src_dtype)` 和 `n * sizeof(dst_dtype)` 计算，mask/repeat 路径还要展开各次真实读写区间。总容量足够与源数据在消费前未被覆盖是两个不同条件。

固定 Cast 文档提醒较短 dtype 转较长 dtype 时地址重叠可能导致错误；它不能被简化为所有重载、产品和输入范围均必然失败。先按当前 API 的地址重叠规则核对，再只将目的 Tensor 改为独立且容量足够的区域，保持源位模式、count/mask、stride 和 RoundMode 不变，比较 Cast 前后首个分叉。若独立目的区消除了错值且地址账本支持覆盖，提高存储候选；若仍失败，按当前支持重载及 Cast 前后位模式继续检查转换链和上游。改变布局同时改变了 tiling、对齐或调度时仍需排除混杂。

若目标写入已经覆盖尚未读取的源数据，调用之后增加 barrier 或更换 RoundMode 都不能恢复它。具体片内读写先后不从这张地址账本推断；生命周期与 alias 的其它分叉见 [Buffer 生命周期、绑定与别名](buffer-lifetime-alias.md)。

## 比例偏差与舍入配置

整数转 half 后出现固定倍率偏差时，先确认实际走普通 Cast 还是反量化路径，并记录当前 scale；不要按历史倍率直接修正。跨产品移植后 float→half 的误差方向改变，则分别核对重载、支持的 RoundMode 和真实配置，用正负半整数附近的样本比较转换前后值。接口被拒或枚举存在但组合不支持时，调用 CANNBOT `ascendc-docs-search` 技能查类型转换规则，不能用 ReinterpretCast 代替数值转换。

### 量化中间精度与参考结果

AscendQuant 的 float→int8 路径可能在内部先把输入、scale、offset 转成 half，具体过程调用 CANNBOT `ascendc-docs-search` 技能查所用量化重载。若比原 CPU 参考误差大，可以建立含 half 中间量的模型来找首次分叉；这个模型用于解释实现，不自动替代任务的验收基准。只有算子定义证明原基准有误时才更正，否则应修复计算路径。

量化输出集中在最大值附近时，分别检查 scale 的解码值、量化前数值和实际饱和模式；不要直接调整 scale 的取整方向。动态统计、scale 与倒数混用等问题见[动态量化](../operators/dynamic-quant.md)，MX/E8M0 另见[精度模式](precision-mode-approximation.md#mxe8m0-边界)。

## 模式名称与 SIMT 转换

模式名称不是无损或实际生效的证明。CANN 9.1 Memory Cast 将有精度损失时的 CAST_NONE 解释为 CAST_RINT；当前 dtype、产品和重载是否允许仍须查询。AscendQuant 的部分可配置舍入路径还存在不支持的 roundMode 回退默认模式且不报错的说明；配置写进源码但结果不随之变化时，先核对组合表，再用 tie 两侧和边界值比较实际位模式，不直接判为编译器忽略配置。

SIMT 转换按精确函数查询，不把 Tensor Cast 的 RoundMode 表或 FP8 的特殊值规则套到 half、BF16、整数转换。对 half2、bfloat16x2 等打包类型，先展开真实分量并对齐输入输出位置，再比较每个分量的舍入、饱和和异常值；只有打包路径失败时，同时保留布局与数值两类候选。

## 判断规则

- Cast 前匹配、Cast 后稳定匹配另一已支持模式，才支持 RoundMode 候选。
- 仅范围外分叉优先检查溢出、饱和和转换契约。
- 扩大中间 dtype 有效、修改最终 Cast 无效，支持过早降精度而不是最终舍入。
- Cast 前已经分叉时，最终 Cast 只能放大或隐藏上游误差，不能被认定为最早根因。

跨 FP16、BF16、FP32 或整数的 A/B 测试同时改变了表示范围、尾数和可能的实现路径，只能用于缩小范围。RoundMode 名称、枚举值、默认行为和 dtype 支持必须查询当前版本的精确重载；旧案例中的固定模式配对只作为待验证主题。

若小增量只在最终升宽前丢失，按需查看 [FP16 升精度：在首次信息损失前改变位置](../cases/fp16-promotion-boundary.md) 的首次窄化对照；仍以当前逐操作合同决定能否调整提升位置。

枚举值存在不代表某个重载、dtype 组合和产品支持它；编译通过也不能替代输出位模式验证。

Cast 的源目的重叠约束调用 CANNBOT `ascendc-docs-search` 技能查目标产品与具体重载，涉及版本差异时再查当前头文件或做最小实验。
