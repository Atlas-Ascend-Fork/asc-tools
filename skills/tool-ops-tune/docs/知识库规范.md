# 知识库规范（tool-ops-tune 知识分类与标准化说明）

> 本文档是套件内全部知识资产的分类标准与入库契约：知识分几类、每类怎么组织、
> 入库门槛是什么、如何被路由到。配套 schema 细则见 `ops-verdict/references/`
> 下三份契约文档（rule-schema / io-contracts / scope-schema）。
> **公共纪律**：新增知识必须先声明路由入口（机制卡索引 / 族分类表 /
> mechanism_refs）——无入口的知识不可被路由到，等于不存在；「暂未收录」
> 显式返回并计数（缺口感知回路输入），禁止静默空结果。

## 1. 知识分类（按消费时机与形态）

| 类别 | 形态 | 落点 | 消费时机 | 交付状态 |
|------|------|------|---------|---------|
| K1 判定规则 | YAML 规则包（脚本求值） | ops-verdict/rules/ | Phase 2 判定 | ✅ L0-L3 四包 24 条 |
| K2 优化机制卡 | 机制卡（固定八要素） | ops-mechanism/references/optimize/ | Phase 3 判定后路由 | 🟡 随优化卡片 PR |
| K3 算子族与模板 | A/B 双型文档 + 代码模板 | ops-family/references/<族>/ | Phase 3-4 实施时 | 🟡 随算子族 PR |
| K4 案例证据 | 案例卡（A-E 证据分级） | ops-mechanism/cases/ | Phase 3 同型检索 | 🟡 随优化卡片 PR |
| K5 外部知识引用 | 引用清单 + 版本锁定（不落副本） | 规划中 adapters/ | 需要事实时运行时探测 | 🟡 框架期落地 |

**K1-K4 与 K5 的分界**：经验性知识（指标→瓶颈→机制因果，不随 API 演进失效）自建沉淀；
事实性知识（芯片参数 / API 签名 / 官方示例 / 理论标尺，随芯片代际演进）一律引用
CANN 生态真源（devkit 文档 / cann-bench metadata / 官方算子仓），本仓只存引用清单
与版本锁定——运行时探测优先（`GetCurNpuArch()` / `GetCoreNumA*` / 本机 `--help`）。

## 2. K1 判定规则：书写规范

规则 = 数据不是代码。新规则 = 一个 YAML 条目 + fixture + 断言用例，零引擎代码改动。

**必填要素**（完整 schema 见 `ops-verdict/references/rule-schema.md`）：

| 要素 | 要求 |
|------|------|
| `id` / `layer` / `priority` | 全局唯一（跨包路由引用）；layer ∈ L0-L3；priority 升序求值 |
| `soc: [a2, a3, a5]` | 芯片域硬过滤；跨芯片阈值差异禁止静默复用 |
| `metrics_required` / `metrics_optional` | 绑定契约：REQUIRED 缺失 → SKIPPED（未采集不判定）；OPTIONAL 缺失 → 降级（反证标 unevaluated） |
| `condition` | any/all 递归三值逻辑（None=证据不足 → INSUFFICIENT_DATA，不冒充「无 bound」） |
| `threshold_source` | 每条阈值可溯源：`[msprof-doc]`（官方文档口径）/ `[tuning-practice]`（实践实测）/ `[mc2-practice]`（多卡实测）/ 🟡（首期标定值）；**无来源合入评审降级 watch 档** |
| `counter_evidence` | **BOUND 类规则必须带反证条目**（防误判第二道闸），否则不允许合入 |
| `severity` bands / `confidence` / `speedup_range` | 分档 + 置信度 + 预估收益区间（校准闭环回写） |
| `mechanism_refs` | 机制路由入口（判定→机制契约）；指向 ops-mechanism 卡片路径 |
| `routing.on_hit` | （可选）路由副作用：命中后禁用其它规则/改道机制路由，跨规则包传播 |

**合入门槛**：`threshold_source` 必填（无实测来源标 🟡）+ fixture 已知答案输入 +
断言用例（正例 + 至少一个反例/边界）+ 回归全绿。

## 3. K2 优化机制卡：固定八要素

| 要素 | 说明 |
|------|------|
| 原理 | 为什么这个机制能消除该瓶颈（硬件层因果链） |
| 适用前提 | 判定证据特征（对应 rule_id + 指标窗口）；架构/容量约束（L1/L0/UB 预算） |
| 预期收益 | speedup_range + 可行性系数（校准闭环回写） |
| 架构限制 | soc 适用域、代际差异（A2/A3/A5 分支） |
| 精度风险 | 语义保持类 / 语义变更类分级；语义变更必须写额外验证用例 |
| 验证命令 | 精度全量 + 同口径性能的具体命令形态 |
| 回滚条件 | 劣化/噪声带/精度失败的处置路径 |
| 模板资产 | 可拷贝代码模板路径（对接 ops-family）或「无货架参考」标注 |

**合入门槛**：八要素写全 + 挂到对应规则的 `mechanism_refs`（rule_id 索引表同步）+
收益区间无实测来源时标 🟡 + 评审通过。

## 4. K4 案例卡：字段与 A-E 证据分级

固定字段：`算子类别 / DSL / 类型（PR|非PR）/ 来源可信度 / 来源链接 + 验证日期 /
瓶颈证据（rule_id 对应）/ 优化机制 / 原文性能数字 / 适用范围与警示`。

| 等级 | 来源 | 可写入 | 禁止 |
|------|------|--------|------|
| A | 官方已合并 PR/MR，含测试表 | 机制、适用平台、原文数字、精度结果 | 把某 shape 收益泛化到全场景 |
| B | 官方 PR/MR，无数字 | 代码机制、文件路径、平台分支 | 推算或补写加速比 |
| C | 官方 Wiki/指南/sample | 推荐流程、可运行案例、原文数字 | 把教程数字当目标设备峰值 |
| D | 社区/二手材料 | 仅作线索与背景，明确警示 | 作为唯一验收证据 |
| E | 本工作流实测回灌 | 机制可信度等同 A；speedup 绑定口径指纹 | 外推到其他口径 |

**检索纪律**：最多取 3 个同型案例；PR 未公开数字统一写「原文未附量化数字」；
**反例与收益案例同等收录**（警示列必填）；无同型案例走降级策略（证据链 + 机制卡
驱动、实施细节自行推导并提高验证强度、报告标注「无同型案例」、沉淀 E 级候选）。

## 5. K3 算子族与模板：入库要求

- 建族目录 `ops-family/references/<family>/` → 判 A 型（单实现调参）或 B 型
  （多实现选型，必须含选型决策树）→ guide + 模板链路 → 族分类表更新；
- 模板（.h/.cpp/.template）抄自官方示例的标来源与许可证头；**查到模板必须直接
  拷贝 + 最小适配，禁止参考重写**（模板优先纪律 T1-T5，编排层同款）；
- 更新策略：追上游引用重拷（上游变了 → 重新评估拷贝版本），不在本仓独立分叉；
- 资产计数防漂移：族表模板数与实际文件数的一致性由静态断言守护（随测试框架 PR
  挂 CI）。

## 6. 知识缺口计数（缺口感知回路输入）

任何子域遇到「暂未收录」必须显式返回并落盘计数（`ops-family/references/
knowledge_gaps.json` 形态，随算子族 PR 交付），禁止静默空结果——缺口数据是
后续知识排产的唯一依据。

## 7. 阈值变更流程（全类别公共）

```
改 YAML/机制卡 → 回归全绿 → 阈值带来源标注 → 人审 → 合入
```

- 无来源合入评审降级 watch 档；缺反证的 BOUND 类规则不允许合入；
- 自进化回路（案例回流 / 校准闭环 / 阈值进化 / 缺口感知）只产生建议不直接生效；
  证据分级不可逆（E 级不覆盖官方 A 级）；数据脱敏；基线库版本化。
