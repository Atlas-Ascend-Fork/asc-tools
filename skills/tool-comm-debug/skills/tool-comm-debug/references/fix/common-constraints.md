# 修复落码与自验

修复要同时恢复通信和业务结果。按现场证据选用下面的核查，不把某个历史用例的补丁当成通用规则；公开任务契约和允许的修改范围优先。

1. **核实正在使用的接口与调用边界。** 以本次构建实际使用的SDK头文件、对应版本文档和已验证用法为准，核对签名、参数单位、设备编号域（用户可见逻辑号、物理卡号与驱动逻辑号）及平台限制。枚举或声明存在不等于当前引擎和设备支持全部组合。接口失败时保留最早返回码和详细错误，区分参数准备、提交执行与等待完成；若现场同时涉及调用方准备逻辑与底层库初始化或属性探测分支，须一并核实底层分支在当前环境的实际返回与特性不支持时的回退路径，把直接故障因果与库侧回退分支范围分别交代清楚。当 ASCEND_RT_VISIBLE_DEVICES 等可见性隔离使各进程本地逻辑卡号从 0 重映射、导致高层跨卡访问或 peer 使能接口因对端不在本进程可见集而报错时，不得将跨卡使能降级为空操作或直接跳过（即便简化冒烟运行表面退出码为 0）；须通盘核查允许修改范围内的底层运行时动态符号封装（物理卡号级接口）与跨 rank 导出描述符/握手元数据（含协议版本号），将本端真实物理卡号随描述符显式传递并在导入侧完成底层跨卡使能。涉及不同芯片代际的硬件阈值、位宽或无效哨兵常量时，应保留既有代际有效常量并新增目标平台专属常量或按芯片类型分支选择，同时核查分支所依赖的芯片类型或拓扑成员在当前初始化函数中的实际赋值先后顺序，确保分支判定前已完成探测赋值。

2. **把同步关系落到实际对象。** 对每个相关stream、event或通知，写清谁生产、谁等待、何时可复用。区分host提交顺序和设备完成顺序；是否允许先等待后发布、Reset或查询代表什么，应依据当前API语义确认，不能把不同原语的规则互相套用。修复须让每次等待对应一个可达的生产动作，并避免覆盖尚在消费的资源。

3. **沿数据实际落点核查。** 从输入到设备计算、通信暂存、跨卡访问、结果缓冲和输出，核对所有者、轮次、有效范围与完成条件。修改收发地址或执行顺序后，再检查下游是否消费修复后的结果；不要只让程序退出成功，却仍返回局部值或旧缓冲。

4. **以公开语义恢复业务。** 保留要求的设备数据面、算子计算、全部rank和轮次。数学语义来自公开说明、调用器和输入元数据，不能仅凭一个闲置通信域就补出某种collective，也不能默认未知归约一定是SUM。缺少决定性契约时说明不确定项，在可确定范围内验证；不通过搜索私有参考、历史补丁或其他会话来补答案。

5. **按参数语义匹配两端。** 先区分全组共同参数、各rank的局部形状、对端形状以及每条消息的范围。仅对API要求相同的字段统一取值；分片长度、目标rank和收发角色可以合法不同。依据公开算子语义和输入元数据推导元素数与布局，再展开字节偏移、长度和缓冲容量。现有代码里的多数值、注释或某个rank的值都只是线索，不自动成为正确值。

6. **确认结果完整且数值正确。** 按公开runner或调用器确定输出位置、文件格式和dtype，检查所有要求的rank、轮次与组件。正常退出、文件存在或大小正确都不能代替数值比较；整数按契约精确比较，浮点按约定误差比较。可以用实际公开输入独立计算参考值供比较，不能把参考写回冒充设备结果。全零、局部连续零、只在后续轮次出错都是定位线索，需结合真实输入解释，不能把合法稀疏结果直接判错。

7. **严守可修改范围并保留有效的错误检查。** 落码与调试前先核对工程公开契约允许修改的文件清单，即使添加临时定位日志也不触碰可修改清单之外的受保护文件，交付前清理所有临时探针。构建与验证优先调用工程既有公开编译/运行入口及系统匹配的构建工具链，不在离线受限环境发起 `curl`、`wget`、`git clone`/`fetch`/`pull` 或联网安装第三方包。不吞掉接口失败，不删除数学验收或篡改输出以求通过。不可修改的调用器或检查存在疑问时，保留证据并报告，不能绕过。

8. **复合故障按实测逐层收敛并联查同源分支。** 复杂状态机或多阶段流水故障不要在未编译运行前单步空想穷举所有阶段：先针对首个明确缺陷最小落码并实机运行，由真实报错或数值差异暴露下一层耦合问题（如空轮询或零迭代路径写回残留状态、门铃未推进等）。当修复涉及按规模分流或新增算法路径时，同步核查同函数既有小规模或回退分支是否存在硬编码扇出度、缺少核内线程/向量通道门限或冗余远端轮询等伴生缺陷。必要时在授权源码中用`rg`查相关调用及rank分支，区分正常分工和违反接口契约的差异；改变一层后用实际输出确认根因是否独立，允许符合公开要求的其他正确协议。

## 产物定位边界

先读取本次调用入口、公开配置或runner明确导出的INPUT_DIR、META_FILE、OUTPUT_DIR，解析变量与工作目录后，只在本例已授权的精确目录读取输入/输出。产物缺失时核对本次退出码、该目录与明确配置；不能扩大到父目录、其他会话、仓库根或全盘扫描来猜输出位置。配置仍不足则说明缺失信息与验证限制，不伪造数值通过。
