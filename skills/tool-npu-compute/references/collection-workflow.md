# npu-compute 采集与报告流程

## 采集前检查

1. 确认目标程序、正常运行的工作目录、程序参数、指标范围和输出位置。必要参数无法从用户请求或程序说明确认时，报告缺项。
2. 用 `--list-sets` 或 `--list-sections` 核对已安装版本支持的指标。名称不可用时，报告实际候选项。
3. 确认目标程序可从指定工作目录启动，检查父目录和报告路径。发现嵌套采集时，定位内层调用。修改目标程序及重采须在已授权范围内。

## 执行并验证

在目标程序所需的工作目录运行采集。解包前确认输入报告存在且可读。记录实际命令、退出状态、产物路径和报错。

| 操作 | 成功判据 |
|---|---|
| 打包采集 | 退出状态为 `0`，`report` 指向实际存在的 `.npu-rep`。 |
| `--no-pack` 采集 | 退出状态为 `0`，`directory` 指向实际交付的结果目录。 |
| 报告解包 | 退出状态为 `0`，`unpacked` 指向实际存在且含可识别产物的目录。 |

使用终端给出的实际路径。目标程序自身运行成功只代表业务程序状态。遇到路径错误、目标程序失败、硬件信息缺失、打包或解包失败时，报告失败阶段和诊断。Application Replay 采集不完整时，保留并标记已交付的产物。

采集收尾时，工具在校验并读取 `summary.jsonl` 后将命中的性能提示写入 `stdout`。打包和 `--no-pack` 均适用。汇报采集结果时，按算子和设备说明实际提示的规则编号、触发指标及其值或条件，以及建议检查方向。按上表核实采集状态。

## 检查结果目录

使用 [目录检查脚本](../scripts/inspect_collection.py)检查解包或直接输出的目录。按根目录、`collection-p...` 子结果、Application Replay 的 `pid-<PID>` 和逐次 launch 路径记录结果。用相对路径区分同名文件，并列出未识别项目。
