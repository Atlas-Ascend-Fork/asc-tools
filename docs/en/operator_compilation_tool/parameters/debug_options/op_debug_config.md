# --op\_debug\_config

<!-- md-trans-meta sourceCommit=2575ba72def56b10b4e28610e3f0129db5bc2da9 translatedAt=2026-10-15T11:24:23.876Z pushedAt=2026-10-16T01:20:29.048Z -->

## Description

Path and name of the debug configuration file.

## Related Parameters

None

## Parameter Values

**Parameter value:** path and name of the configuration file.

**Parameter value format:** path and file name, which can contain uppercase and lowercase letters (a-z, A-Z), digits (0-9), underscores (\_), hyphens (-), periods (.), and Chinese characters.

**Parameter value constraints:**

The configuration file supports the following options, separated by commas.

- **oom**: during operator **execution**, checks whether Global Memory is accessed out of bounds.
    - When you configure this option, during operator build, the .o (operator binary) and .json (operator description) files are retained in the **kernel\_meta** folder generated by operator build in the current execution path.
    - After this option is used, the following check logic is added during operator build. You can use the **dump\_cce** parameter to view the following code in the generated .cce file.

        ```cpp
        inline __aicore__ void  CheckInvalidAccessOfDDR(xxx) {
            if (access_offset < 0 || access_offset + access_extent > ddr_size) {
                if (read_or_write == 1) {
                    trap(0X5A5A0001);
                } else {
                    trap(0X5A5A0002);
                }
            }
        }
        ```

        During actual inference, if out-of-bounds memory access actually occurs, the "**EZ9999**" error code is reported.

- **dump\_bin**: during operator build, the .o (operator binary) and .json (operator description) files are retained in the **kernel\_meta** folder generated by operator build in the current execution path.
- **dump\_cce**: During operator build, the operator .cce file **\*.cce**, as well as the .o (operator binary) and .json (operator description) files, are retained in the **kernel\_meta** folder generated by operator build in the current execution path.
- **dump\_loc**: During operator build, the python-cce mapping file **\*\_loc.json** is retained in the **kernel\_meta** folder generated by operator build in the current execution path.
- **ccec\_O0**: During operator build, the ccec compiler option **-O0** is enabled. Configuring this option **does not** optimize the debug information, and it is used for subsequent analysis of AI Core error issues.
- **ccec\_g**: During operator build, the ccec compiler option **-g** is enabled. Configuring this option **does** optimize the debug information, and it is used for subsequent analysis of AI Core error issues.
- **check\_flag**: During operator **execution**, checks whether the internal pipeline synchronization signals of the operator match.
    - When this option is configured, during operator build, the .o (operator binary) and .json (operator description) files are retained in the **kernel\_meta** folder generated by operator build in the current execution path.
    - After this option is used, the following check logic is added during operator build. You can use the **dump\_cce** parameter to view the following code in the generated .cce file.

        ```cpp
          set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
          set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
          set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
          set_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
          ....
          pipe_barrier(PIPE_MTE3);
          pipe_barrier(PIPE_MTE2);
          pipe_barrier(PIPE_M);
          pipe_barrier(PIPE_V);
          pipe_barrier(PIPE_MTE1);
          pipe_barrier(PIPE_ALL);
          wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID0);
          wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID1);
          wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID2);
          wait_flag(PIPE_MTE3, PIPE_MTE2, EVENT_ID3);
          ...
        ```

        During actual inference execution, if the internal pipeline synchronization signals of the operator do not match, a timeout error is eventually reported **at the faulty operator and the program is terminated**. An example of the error message is as follows:

        ```text
        Aicore kernel execute failed, ..., fault kernel_name=operator name,...
        rtStreamSynchronizeWithTimeout execute failed....
        ```

> [!NOTE] Note
>
> - When the ccec compilation options (that is, the **ccec\_O0** and **ccec\_g** options) are configured, the size of the operator kernel (the **\*.o** file) increases. In dynamic shape scenarios, all possible shape scenarios are traversed during operator build, which may cause the operator kernel file to be too large to compile. In this case, it is recommended that you do not configure the ccec compilation options.
>   The following is an example of the error log reported when the operator kernel file is too large to compile:
>
>   ```text
>   message:link error ld.lld: error: InputSection too large for range extension thunk ./kernel_meta_xxxxx.o:
>   ```
>
> - The ccec compilation option **ccec\_O0** and the **oom** option cannot be enabled at the same time. Otherwise, an AI Core error is reported. The following is an example of the error message:
>
>   ```text
>   ...there is an aivec error exception, core id is 49, error code = 0x4 ...
>   ```
>
> - The **oom** configuration option cannot be used together with the **NPU\_COLLECT\_PATH** environment variable. Otherwise, an error occurs when the compiled operator kernel package is used.

## Examples

Assume that the configuration file for enabling the Global Memory detection function is named **_gm\_debug.cfg_**. The following is an example of the file content configuration:

```text
op_debug_config=ccec_g,oom
```

Upload the file to the server where the compilation tool resides, for example, to **_$HOME/module_**. The following is an example of its usage:

```bash
op_compiler --kernel_name=<kernel_name>  --op_debug_config=gm_debug.cfg --soc_version=<soc_version> --log=info --job=128  --output=<output_dir>
```
