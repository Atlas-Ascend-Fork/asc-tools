# msobjdump

## Overview

This tool provides parsing, extraction, and AI Core instruction disassembly capabilities for generated operator ELF files (Executable and Linkable Format), presenting the results in a readable format so that developers can intuitively obtain kernel file information. For a detailed introduction of this tool, please refer to the "Programming Guide > Appendix > msobjdump Tool" section in [Ascend C Operator Development](https://hiascend.com/document/redirect/CannCommunityOpdevAscendC).

For a tool usage demonstration, refer to the [msobjdump example](../../examples/04_msobjdump/README_en.md).

When using this tool through an Agent, refer to the [tool-npu-objdump Skill](../../skills/tool-npu-objdump/SKILL.md) for environment preparation, command selection, and metadata interpretation.

## Command Format

- Command to parse an ELF file

    ```bash
    msobjdump --dump-elf ${elf_file} [--verbose]
    ```

    | Parameter (case-sensitive) | Required/Optional | Description |
    | ---- | ---- | ---- |
    | `--dump-elf ${elf_file}`, `-d` | Required | Parse and display device information contained in the ELF file.<br>`${elf_file}` specifies the path of the ELF file to parse. |
    | `--verbose`, `-V` | Optional | Use with `--dump-elf` to print all device information in the ELF file. |

- Command to extract an ELF file

    ```bash
    msobjdump --extract-elf ${elf_file} [--out-dir ${out_path}]
    ```

    | Parameter (case-sensitive) | Required/Optional | Description |
    | ---- | ---- | ---- |
    | `--extract-elf ${elf_file}`, `-e` | Required | Extract device information from the ELF file and save the results to the output directory.<br>`${elf_file}` specifies the path of the ELF file to extract. The default output directory is the current working directory. |
    | `--out-dir ${out_path}`, `-o` | Optional | Use with `--extract-elf` to specify the output directory for extracted files. The specified directory must already exist and be writable; the tool does not create it. If omitted, the current working directory is used. |

- Command to list ELF file contents

    ```bash
    msobjdump --list-elf ${elf_file}
    ```

    | Parameter (case-sensitive) | Required/Optional | Description |
    | ---- | ---- | ---- |
    | `--list-elf ${elf_file}`, `-l` | Required | List the device information files contained in the ELF file.<br>`${elf_file}` specifies the path of the ELF file to list. |

- Command to disassemble AI Core instructions

    ```bash
    msobjdump --sass ${input_file} [--lineinfo] [--source]
    ```

    | Parameter (case-sensitive) | Required/Optional | Description |
    | ---- | ---- | ---- |
    | `--sass ${input_file}` | Required | Disassemble the input ELF file to display Device-side AI Core instructions. `${input_file}` specifies the path of the ELF file to disassemble. |
    | `--lineinfo` | Optional | Use with `--sass` to display source file names and line numbers alongside the disassembly. Compile the operator with `-g` to generate debug information. |
    | `--source`, `-s` | Optional | Use with `--sass` to display the corresponding source code alongside the disassembly. Compile the operator with `-g` to generate debug information, and make sure the source files are accessible at the paths recorded in the debug information. |

    Supported inputs include standalone Device ELF files, Host ELF files generated by fusion compilation (such as the executable `demo` or the shared library `libcustom.so`), static archives such as `libkernels.a`, and container files containing `.aicore_binary`, `.ascend.kernel.*`, or `_o/_json` data. For Host ELF files and archives, the tool automatically traverses and extracts the contained Device ELF files before disassembly. An error is returned if no Device ELF is found in the input.

    `--sass` cannot be combined with `--dump-elf`, `--extract-elf`, `--list-elf`, `--verbose`, or `--out-dir`. The output is written to standard output by default and can be saved with shell redirection. Thin archives are not supported.

    The primary command is `npu-objdump`. The installation package also provides `msobjdump`, a symbolic link to `npu-objdump` retained for compatibility with existing usage. Both commands support the same arguments and processing logic. Only the `--sass` long option is provided; there is no `-sass` alias.

    `--lineinfo` and `--source` depend on debug information in the Device ELF. Compile the operator with `-g` to generate debug information; see [Common compilation options](https://gitcode.com/cann/asc-devkit/blob/master/docs/zh/guide/programming_guide/compilation_and_execution/operator_compilation/ai_core_operator_compilation.md#ZH-CN_TOPIC_0000002462746461) and [Custom compilation options](https://gitcode.com/cann/asc-devkit/blob/master/docs/zh/guide/programming_guide/advanced_programming/aclnn_operator_development/compilation_and_deployment/basic_process.md#custom-compile-options) for configuration details. Even if the ELF contains no debug information, `--sass` can still disassemble instructions. In that case, `--lineinfo` cannot display source locations and `--source` cannot display source code. When `--source` is used and a source file recorded in the debug information is inaccessible, the tool prints a warning and continues disassembly without the corresponding source code.


The following table describes common fields in ELF files:

| Field Name | Description | Required | Print Behavior |
| ---- | ---- | ---- | ---- |
| `.ascend.meta. ${id}` | Represents the operator kernel function name, where `${id}` is the index of the meta information. | Yes | Printed by default without `--verbose`. |
| `VERSION` | Represents the version number. | Yes | Printed by default without `--verbose`. |
| `DEBUG` | Debug-related information, consisting of two parts:<br>`debugBufSize`: Memory space required for debug information.<br>`debugOptions`: Debug switch status. Values:<br>`0`: Debug switch off.<br>`1`: Debugging via DumpTensor and printf.<br>`2`: Debugging via assert.<br>`4`: Debugging via timestamp marking.<br>`8`: Debugging via memory out-of-bounds detection. | No | Printed by default without `--verbose`. |
| `DYNAMIC_PARAM` | Whether the operator kernel function uses dynamic parameters. Values:<br>`0`: Dynamic parameter mode off.<br>`1`: Dynamic parameter mode on. | No | Printed by default without `--verbose`. |
| `OPTIONAL_PARAM` | Optional parameter information, consisting of two parts:<br>`optionalInputMode`: Whether optional inputs require placeholders in the operator kernel function.<br>`0`: Optional inputs do not occupy placeholders.<br>`1`: Optional inputs occupy placeholders.<br>`optionalOutputMode`: Whether optional outputs require placeholders in the operator kernel function.<br>`0`: Optional outputs do not occupy placeholders.<br>`1`: Optional outputs occupy placeholders. | No | Printed by default without `--verbose`. |
| `KERNEL_TYPE` | Represents the core type used at kernel function runtime. | No | Printed by default without `--verbose`. |
| `CROSS_CORE_SYNC` | Represents the hardware synchronization syncall type. Only available for Atlas A2/A3 series.<br>`USE_SYNC`: Use hardware synchronization.<br>`NO_USE_SYNC`: Do not use hardware synchronization. | No | Printed by default without `--verbose`. |
| `MIX_TASK_RATION` | Represents the Cube core/Vector core ratio allocation type during kernel function execution. | No | Printed by default without `--verbose`. |
| `DETERMINISTIC_INFO` | Indicates whether the operator uses deterministic computation.<br>`0`: Non-deterministic computation.<br>`1`: Deterministic computation. | No | Printed by default without `--verbose`. |
| `BLOCK_NUM` | Represents the number of execution cores. This field is currently not supported and only prints the default value `0xFFFFFFFF`. | No | Printed by default without `--verbose`. |
| `FUNCTION_ENTRY` | The value of the operator TilingKey. | No | Printed by default without `--verbose`. |
| `elf header infos` | Includes ELF Header, Section Headers, Key to Flags, Program Headers, Symbol table, and other information. | No | Set `--verbose` to enable full printing. |
