# Contribution Guide

This project welcomes you to experience and contribute. Before contributing to the community, see [cann-community](https://gitcode.com/cann/community) to learn about the code of conduct, sign the CLA, and learn about the source repository contribution process. In addition to the contribution scenarios listed in this guide, you can also get deeply involved in building the CANN community through the community's [Basic Contributions](https://gitcode.com/cann/community#基础贡献) (such as attending community meetings, joining email discussions, and submitting Issues/PRs) or [Advanced Contributions](https://gitcode.com/cann/community#进阶贡献) (such as creating a SIG or becoming a core contributor, organizing meetings, creating repositories, and configuring CI).

Pay attention to the following points when you prepare local code and submit a PR:

1. When you submit a PR, fill in the business background, purpose, and solution of the PR as required by the PR template.
2. If your change is not a simple bug fix, but adds features, APIs, configuration parameters, or changes code flows, discuss the solution in an Issue first. This prevents your code from being rejected. If you are not sure whether the change can be classified as a "simple bug fix", you can also submit an Issue for discussion.


The main contribution scenarios include the following:

- Bug fixes

  If you find bugs in this project and want to fix them, you are welcome to create an Issue for feedback and tracking.

  Create a `Bug-Report|缺陷反馈` Issue as guided in [Submit/Process Issue Tasks](https://gitcode.com/cann/community#提交Issue处理Issue任务) and describe the bug. Then enter "/assign" or "/assign @yourself" in the comment box to assign the Issue to yourself.

- Code optimization

  If you have ideas for improving the generalization or performance of certain APIs in this project, you are welcome to contribute API optimizations.

  Create a `Requirement|需求建议` Issue as guided in [Submit/Process Issue Tasks](https://gitcode.com/cann/community#提交Issue处理Issue任务) to describe the optimization points and provide your design solution.
  Then enter "/assign" or "/assign @yourself" in the comment box to assign the Issue to yourself for tracking.

- Documentation corrections

  If you find documentation errors in this project, you are welcome to create an Issue for feedback and fixes.

  Create a `Documentation|文档反馈` Issue as guided in [Submit/Process Issue Tasks](https://gitcode.com/cann/community#提交Issue处理Issue任务) to point out the documentation problem. Then enter "/assign" or "/assign @yourself" in the comment box to assign the Issue to yourself for correction.

- Helping others resolve Issues

  If you have a proper solution to a problem raised by others in the community, you are welcome to comment on the Issue to help resolve it.

  This helps others resolve problems and pain points and improves usability.

  If the Issue requires code changes, enter "/assign" or "/assign @yourself" in the Issue comment box to assign the Issue to yourself and help resolve it.
